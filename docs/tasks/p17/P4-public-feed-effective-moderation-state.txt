GOAL
Make the existing canonical public feed consume Phase 17 effective headline and effective Category membership while preserving all existing feed eligibility, duplicate suppression, discovery, ordering, pagination, and original-publisher navigation behavior.

P4 must modify the canonical feed path rather than introduce a moderation-specific feed or post-filtering layer.

EFFECTIVE HEADLINE
For every eligible public Article:
- public `headline` is the active Phase 17 display-title override when present;
- otherwise public `headline` is the latest Source-derived `articles.display_title`;
- `original_url` remains the stored publisher destination and is never replaced by the override.

Keyword search must include the effective headline while preserving previously supported Source-derived searchable representations. Do not silently remove normalized title, author, summary, or other existing governed search inputs merely because the public headline can be overridden.

An active override should be able to match `q` even when the underlying Source title does not. Clearing it immediately returns display/search behavior to the latest Source-derived state.

EFFECTIVE CATEGORY MEMBERSHIP
For Category filtering:
- if an active manual Article Category override marker exists, use only its manual memberships as the Article's effective current Category set;
- if no active marker exists, use the latest automatic `article_categories` memberships;
- an active intentionally empty manual set matches no Category;
- clearing the override immediately returns filtering to the latest automatic state;
- retained historical observation Category reasons never make an Article match by themselves.

Do not overwrite/copy automatic memberships when reading effective state.

PRESERVE CANONICAL ELIGIBILITY
Keep the existing eligibility rules unchanged except for effective display/Category read semantics:
- singleton Publication must be public;
- Source approval/lifecycle rules remain as currently governed;
- Article must be visible;
- visible non-Primary Duplicate-group members remain suppressed;
- visible ungrouped and visible Primary Articles remain eligible;
- hiding the current Primary does not promote or resurrect a visible non-Primary;
- manual Primary changes from P3 affect representation only through the canonical existing group Primary relation.

PRESERVE DISCOVERY / CURSORS
Do not change:
- public query vocabulary (`q`, `source`, `category`, `cursor`);
- validation bounds/duplicate-key rejection;
- Source filter by immutable Source `config_key`;
- Category filter by immutable Category `config_key`;
- AND composition of `q + source + category`;
- effective-feed-date -> `first_seen_at` -> Article-ID ordering;
- opaque/versioned query-bound cursor semantics;
- page size/load-more behavior;
- public Source/Category choice bounds;
- root `/` and canonical `/api/feed` routing.

Do not apply effective Category filtering after pagination. Eligibility/filtering must remain inside the canonical pre-pagination result stream.

IMPLEMENTATION BOUNDARY
Prefer changing only `src/public-feed/repository.ts` and the narrow tests/read-model types required by the effective-state query.

Reuse a P2 effective-state helper only if it remains a true shared read primitive and does not force admin pagination/provenance concerns into the public feed. Direct SQL composition in the canonical feed query is acceptable when it is clearer and avoids a second N+1 read path.

Do not modify P1/P2 persistence semantics merely to make the public query easier.

FOCUSED TESTS

- no display override -> Source `display_title` remains headline;
- active display override -> override is headline while `original_url` is unchanged;
- Source title updates under active override do not change effective headline;
- clear -> latest Source title becomes headline;
- `q` can match an active override and still preserves existing search inputs;
- automatic Category membership works when no manual override exists;
- active manual Category membership replaces automatic effective membership for filtering;
- active empty manual Category set matches no Category;
- automatic Category changes under active override do not leak into public filtering;
- clear -> latest automatic Category membership immediately controls filtering;
- historical observation reasons do not create Category matches;
- visible non-Primary rows remain suppressed under all `q`/Source/Category combinations;
- hidden Primary does not resurrect a non-Primary;
- manual Primary changes select the correct member through existing topology;
- tie-heavy pagination/cursor behavior has no duplicate/omitted rows after the effective-state joins;
