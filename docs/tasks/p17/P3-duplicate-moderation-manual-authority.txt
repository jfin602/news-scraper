GOAL
Implement reversible human duplicate moderation while making Phase 16 automatic grouping obey durable Phase 17 manual authority.

P3 owns Duplicate review queue/detail reads, manual dismiss, manual merge, manual split, choose-Primary, manual-authority integration into automatic grouping, and transactional change history for those material actions.

P3 does not expose HTTP routes or browser UI and does not change the public feed directly.

ONE TOPOLOGY OWNER
Keep one canonical cross-process transaction/lock owner for all Duplicate-group membership and Primary mutation.

Prefer extending/refactoring the existing `src/deduplication/grouping.ts` internals only as much as necessary so automatic and manual operations share:
- the database-wide topology advisory transaction lock;
- stable Article/group/candidate row locking/re-read;
- membership/Primary integrity checks;
- deterministic automatic Primary selection where automatic authority is allowed.

Do not build a second manual merge/split implementation with independent lock semantics. Do not use process-local mutexes as the correctness boundary.

AUTOMATIC GROUPING MUST RESPECT MANUAL SEPARATION
Before automatic grouping adds a member or merges two existing groups, determine the complete topology components that would become one group after the operation.

Automatic grouping must not perform the topology change when any active P1 manual-separation pair would end with both Articles inside that resulting group.

This check must protect indirect regrouping. Example: if A was manually separated from C, strong automatic evidence B-C cannot merge group `{A,B}` with C and thereby defeat the manual decision even though the evidence pair is B-C.

When an active separation blocks automatic grouping:
- do not mutate memberships/Primary;
- do not erase separation state;
- keep the evidence/candidate inspectable for operator resolution;
- return a bounded deterministic non-grouping outcome suitable for collection composition rather than converting a manual policy decision into an unbounded database failure.

Materially changed evidence may become reviewable according to existing review rules, but it still cannot automatically defeat active separation authority.

AUTOMATIC PRIMARY AUTHORITY
`duplicate_groups.primary_article_id` remains the only actual Primary ID. P1 authority origin says whether the current valid choice is manual or automatic.

Update automatic topology behavior as follows:
- same-group reevaluation retains a valid manual Primary and does not call the automatic selector over it;
- adding an ungrouped Article to a manually-Primaried group retains that manual Primary;
- merging one manual-Primary group with one automatic group retains the manual Primary;
- merging two automatic groups uses the existing canonical deterministic selector;
- automatic evidence connecting two groups with distinct valid manual Primaries must not merge them automatically.

For the conflicting-manual-Primary case, preserve both groups and expose the evidence for explicit operator resolution. Do not silently choose by UUID, Source priority, recency, or another automatic tie-break.

Do not launch installation-wide Primary reselection when Source priority changes.

DUPLICATE REVIEW QUEUE / DETAIL
Add bounded immutable reads over the existing review candidates/signals sufficient for later API/UI moderation.

Support bounded filters needed by the Phase 17 workflow, such as state/confidence and stable continuation. Include:
- candidate ID and canonical pair;
- current state/origin/manual decision metadata;
- confidence/evidence fingerprint as appropriate;
- ordered bounded signals/reason codes/strength;
- bounded Article summaries for both sides;
- current group/membership/Primary context;
- whether active manual separation or conflicting manual Primary authority blocks automatic grouping.

Do not invent new fuzzy/semantic duplicate evidence or reclassify Phase 16 evidence thresholds.

MANUAL DISMISS
Implement explicit dismiss against an actionable review candidate.

Requirements:
- lock/re-read candidate state transactionally;
- reuse the existing candidate `dismissed` state plus `manual_decided_at` and optional bounded manual reason fields;
- preserve evidence/signals/fingerprint;
- unchanged evidence remains dismissed through the existing detector behavior;
- append one bounded audit event in the same transaction only when a material decision is recorded;
- deterministic invalid/already-incompatible states return bounded conflict/no-op results rather than corrupting topology.

MANUAL MERGE
Implement an explicit operator merge command for selected Articles/current groups through the same topology lock.

The command may combine ungrouped Articles, existing groups, or both, but must preserve:
- at-most-one group membership per Article;
- every Article and observation;
- visibility independently;
- one valid Primary member in the resulting group;
- one deterministic surviving group container when existing groups are combined.

Manual merge intentionally revises active manual separations contradicted by the requested resulting group. Remove only those separation rows that would otherwise forbid Articles intentionally placed into that merged group, and record the material change in audit history.

Primary resolution for manual merge:
1. if the command explicitly names a Primary, validate it is in the resulting member set, set it, and mark authority `manual`;
2. if no explicit Primary and exactly one existing valid manual Primary survives across all components, retain it and retain manual authority;
3. if no explicit Primary and no existing manual Primary, use the current canonical automatic selector and mark authority `automatic`;
4. if no explicit Primary and multiple different manual Primaries would survive, reject with a bounded conflict requiring an explicit Primary choice.

Do not silently discard a manual Primary merely to make an automatic merge convenient.

MANUAL SPLIT
Implement split as removal of selected member(s) from one existing Duplicate group into individually ungrouped Articles.

Requirements:
- use the same topology lock and re-read current membership before mutation;
- at least one selected member must currently belong to the target group;
- selected members become ungrouped individually; P3 does not create new subgroup clusters from one split command;
- if two or more members remain, keep the residual group;
- if fewer than two members remain, dissolve the residual group container and remove the last residual membership so no one-member Duplicate group remains;
- create canonical manual-separation authority between formerly co-grouped Articles that the operation leaves in different resulting topology components, so materially unchanged automatic evidence cannot immediately reconstruct the group;
- do not change Article visibility, Source-derived data, Categories, display overrides, or observations.

If the removed member was the manual Primary and a residual group with at least two members survives, choose a new Primary deterministically through the existing automatic selector and mark the residual group authority `automatic`. Do not infer a new manual choice.

CANDIDATE COHERENCE AFTER SPLIT
A directly affected existing candidate must not remain `merged` when its pair no longer shares one group.

For existing candidate pairs directly separated by the split:
- preserve evidence/signals/fingerprint;
- transition them to `dismissed` with manual decision time/reason semantics consistent with the split;
- unchanged detector evidence must therefore remain dismissed;
- materially changed evidence may later become reviewable under the existing detector rules, but active manual separation still blocks automatic regrouping.

Do not fabricate duplicate review rows for every possible pair that has never had evidence. Manual separation is the durable topology authority; candidate disposition is updated only where a candidate already exists and would otherwise become semantically false.

CHOOSE PRIMARY
Implement explicit choose-Primary for one current Duplicate group.

Requirements:
- lock/re-read group/members through the topology gate;
- validate requested Article is a current member;
- update only the existing `primary_article_id` plus authority origin `manual`;
- preserve memberships and visibility;
- append one bounded audit event atomically;
- repeated identical choose requests should not manufacture duplicate material history.

AUDIT / FAILURE ATOMICITY
Manual dismiss/merge/split/choose-Primary must write required bounded `audit_events` inside the same transaction as the governed mutation.

If audit persistence or any later invariant check fails, roll back candidate/manual-authority/topology/Primary changes together.

Do not write success history for failed/no-op commands.
