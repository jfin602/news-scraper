GOAL
Expose the governed Phase 17 Article and duplicate moderation services through the existing Cloudflare-Access-perimeter-compatible `/api/admin` application boundary.

P5 owns strict HTTP input parsing, route registration, bounded response/error shaping, and Web process composition only. P2/P3 continue to own persistence, transactions, effective state, topology, manual authority, and audit behavior.

ADMIN PERIMETER
Reuse the existing central admin router and middleware.

Do not:
- add native authentication/session/roles;
- inspect or trust arbitrary Cloudflare identity headers as application user identity;
- duplicate the mutation-integrity middleware inside each route;
- weaken the existing JSON body limit/CSP/admin-disabled behavior;
- expose these routes outside `/api/admin`.

Every unsafe moderation request must still be rejected by the central request-integrity boundary when the required header is absent/incorrect.

ARTICLE API SURFACE
Expose a small explicit resource/command surface consistent with current admin conventions. Exact route spelling may adapt to existing style, but preserve these semantics:

1. stored Article list/search
- `GET /api/admin/articles`
- parse only the P2 governed filters/cursor;
- reject unknown/repeated/malformed/out-of-bound query keys;
- return bounded items plus continuation metadata, never an unbounded dump.

2. Article detail
- `GET /api/admin/articles/:articleId`
- return the P2 bounded detail/provenance/effective-state read model.

3. visibility
- one explicit mutation route that can request only governed `hidden` or `visible` transition semantics, or equally explicit hide/restore action routes;
- archived state is read-only here and cannot be converted accidentally.

4. display-title override
- explicit set route accepting only the one governed override field;
- explicit clear route;
- no generic Article patch object.

5. Category override
- explicit set route accepting only bounded Category `config_key` array/list plus optional bounded reason if the P2 service supports it;
- empty list is valid active-empty state;
- explicit clear route remains distinct.

6. change history
- bounded/paginated Article-target history read, either embedded where P2 already returns it or through a dedicated GET route when needed for pagination.

DUPLICATE API SURFACE
Expose explicit P3 read/command routes:

1. `GET /api/admin/duplicate-reviews`
- bounded review queue/filter/cursor.

2. `GET /api/admin/duplicate-reviews/:candidateId`
- bounded candidate/evidence/Article/topology detail.

3. dismiss
- explicit unsafe command on one candidate accepting only optional bounded reason fields already governed by P3.

4. manual merge
- explicit unsafe command accepting a bounded set of Article IDs/current components, optional explicit Primary Article ID, and optional bounded reason;
- no arbitrary membership SQL/topology patch body.

5. split
- explicit unsafe command scoped to one current group and bounded selected member IDs plus optional bounded reason.

6. choose Primary
- explicit unsafe command scoped to one current group with one Article ID plus optional bounded reason.

Stable group/candidate/Article UUIDs are acceptable resource identities for these internal admin routes. Do not add Publication selectors/slugs.

STRICT INPUT VALIDATION
All request parsing must fail closed.

At minimum reject:
- invalid UUIDs;
- unknown/repeated query keys;
- unexpected JSON properties;
- missing required keys;
- duplicate/unbounded Article/Category ID/key arrays;
- malformed cursor/search/filter values;
- invalid visibility action;
- empty merge/split sets where the service contract requires members;
- malformed/oversize reasons;
- invalid explicit Primary values.

Do not pass raw Express objects/body dictionaries into repositories.

ERROR CONTRACT
Translate governed errors into small stable JSON without SQL/stacks/internal paths.

Use:
- `400` for malformed/invalid request input;
- `404` for missing Article/candidate/group resources;
- `409` for valid requests that conflict with current durable state/topology/manual authority, including stale membership or unresolved conflicting manual Primaries;
- `403` remains owned by central request-integrity middleware;
- unexpected persistence/service failures propagate to the existing generic service-unavailable/error boundary rather than leaking details.

Do not convert unexpected database corruption/invariant failures into a misleading 400/404.

Preserve the current `adminEnabled` behavior: when admin is disabled, neither page nor API moderation surface is reachable.

Do not change public `/`, `/api/feed`, health endpoints, or Worker behavior.
