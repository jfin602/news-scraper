GOAL
Add the smallest durable persistence foundation required by Phase 17 while preserving Source-derived Article values, automatic Category state, Phase 16 duplicate topology, and provenance.

P1 owns schema and focused persistence primitives only. It does not expose moderation services, APIs, public-feed behavior, or browser UI.

CANONICAL REPRESENTATION
Add one new migration after `0012_duplicate_persistence_foundation.sql`, expected as `migrations/0013_article_duplicate_moderation.sql` unless the current migration chain has advanced before execution.

Implement these states without speculative generic frameworks:

1. ARTICLE DISPLAY TITLE OVERRIDE
- Add nullable `articles.display_title_override`.
- It is a human-facing headline override only.
- Apply the same trimmed/non-empty/bounded shape discipline as `display_title` when non-null.
- Do not modify or replace `display_title`, `normalized_title`, `original_url`, identity fields, Source ownership, timestamps, or observation provenance.

2. MANUAL CATEGORY OVERRIDE
- Add an `article_category_overrides` table whose Article row presence means manual Category authority is active.
- The marker must support an intentionally empty effective Category set; therefore absence of memberships is valid while the marker exists.
- Add `article_category_override_memberships` for the operator-selected effective Category set.
- Memberships reference the active override Article and current Category rows with uniqueness preventing duplicates.
- Do not repurpose `article_categories`; it remains the latest automatic Relevance/default Category assignment maintained by collection.

3. MANUAL DUPLICATE SEPARATION
- Add `duplicate_manual_separations` using one canonical unordered low/high Article pair.
- Reject self-pairs and reversed/noncanonical persisted order.
- Enforce pair uniqueness so repeated manual separation is idempotent at persistence level.
- Retain bounded decision metadata sufficient for the operator action, including decision time and optional bounded reason where appropriate.
- This table is manual authority consumed by P3; P1 does not implement topology behavior yet.

4. PRIMARY AUTHORITY ORIGIN
- Keep `duplicate_groups.primary_article_id` as the sole actual Primary Article identifier.
- Add only bounded authority metadata such as `primary_selection_origin` with allowed values `automatic` and `manual`, defaulting existing/new groups to `automatic`.
- Do not add `manual_primary_article_id`, role columns on memberships, or another competing Primary source.
- Preserve the existing deferred Primary-membership invariant.

5. APPLICATION CHANGE HISTORY
- Add `audit_events` as append-only application change-history storage for successful material Phase 17 moderation mutations.
- Use UUID identity, bounded action, bounded target type, target UUID, timestamp, optional bounded reason, and bounded prior/new state where useful.
- JSON/JSONB prior/new state is acceptable only with a concrete database/application bound; do not create an unbounded dumping ground for arbitrary request bodies or internal objects.
- Do not add native administrator/user identity, Cloudflare identity, IP address, session, role, or retention/pruning machinery.
- P1 establishes storage only; later prompts own transactional writes and bounded reads.

CONSTRAINTS / INDEXES
Prefer database constraints for expressible integrity and only indexes justified by the planned Phase 17 reads/mutations.

At minimum protect:
- display-title-override shape;
- one active Category override marker per Article;
- unique Category membership per active Article override;
- valid Article/Category references;
- canonical low/high manual-separation ordering and pair uniqueness;
- valid Primary selection origin;
- bounded/non-empty audit action and target type;
- bounded optional reason and prior/new state representation.
