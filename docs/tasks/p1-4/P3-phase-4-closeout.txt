## Pass 1 — Contract and evidence review

Review the integrated implementation against every Phase 4 roadmap exit condition and the permanent v1 machine-interface contract.

### Permanent route and request grammar

Verify:

- only `GET /api/v1/distribution/{profile_key}` plus optional single `cursor` is the permanent v1 distribution route;
- no Source/Category/q/limit/offset/sort/Publication selector reconstruction exists;
- malformed, repeated, ambiguous, unsupported, and out-of-bound request input is rejected boundedly;
- bearer credentials are consumed only from Authorization through the Phase 3 guard and never from query/path/body/cookies;
- no legacy/reference `/` or `/api/feed` behavior was repurposed into the machine API.

### Thin producer composition

Trace the real call chain and require:

`HTTP route -> Phase 3 request guard -> Phase 2 Profile page service -> explicit v1 serializer`

Verify the HTTP/runtime layers do not reimplement:

- credential token parsing, verifier derivation/comparison, authentication lookup, expiry/revocation/capability interpretation, quota counters, or Profile-specific credential authorization;
- Profile child-table SQL, canonical Article eligibility, Profile filters, effective Categories, ordering, result bounds, cursor payload semantics, continuation position, snapshot-revision generation, or `snapshot_changed` detection.

A consumer-friendly adapter is allowed; a second business-rule authority is not.

### v1 success schema and compatibility

Verify every `200` response has stable exact presence for:

- `apiVersion`, `generatedAt`, `snapshotRevision`;
- `profile.configKey`, `profile.displayName`;
- `publication.name`;
- `items`, nullable `nextCursor`;
- every required Article field including nullable `publishedAt`, `author`, `summary`, `imageUrl` and explicit `categories[]`.

Verify:

- chosen `apiVersion` literal is consistent and test-locked;
- all Date values serialize as intended absolute ISO timestamps;
- missing nullable metadata is JSON `null`, not omitted;
- empty arrays remain `[]`;
- exact stored `originalUrl` is preserved;
- internal lifecycle/IDs/SQL/canonical identity/duplicate/Relevance/moderation/provenance/auth data are not leaked;
- implementation does not spread broad repository objects into public JSON.

### Response classes and lifecycle semantics

Verify exact bounded mapping for:

- `200` valid active result including empty output;
- `304` unchanged authenticated initial conditional request;
- `400` malformed request/invalid cursor;
- `401` generic invalid/revoked/expired/unusable credential;
- `404` nonexistent/non-readable draft Profile without private lifecycle disclosure;
- `409 profile_disabled`;
- `409 snapshot_changed`;
- `429` with positive integral `Retry-After` from Phase 3;
- `503` bounded dependency/service failure.

Require no Profile-specific `403` or credential↔Profile matrix.

### Snapshot, cursor, ETag, and conditional behavior

Verify:

- ETag derives from the existing Phase 2 `snapshotRevision`, not a competing HTTP hash;
- matching `If-None-Match` can produce bodyless `304` only for an authenticated initial request;
- cursor continuation never becomes `304` merely because a conditional header matches;
- malformed conditional headers fail/are ignored according to one bounded tested HTTP policy without leaking state;
- stale continuation still becomes `409 snapshot_changed`;
- multi-page traversal cannot mix revisions;
- cursor internals remain opaque to consumers.

### Authentication, limiter lifetime, and network trust

Verify:

- one long-lived Phase 3 machine request guard exists per Web process/runtime composition and is not recreated per request;
- authenticated buckets are keyed by non-secret credential identity;
- invalid-auth protection uses only a bounded HTTP-owned network identity;
- untrusted clients cannot spoof that identity through forwarding headers;
- trusted proxy support, if present, is explicit and bounded;
- bearer plaintext is never a limiter key;
- one credential does not consume another credential's authenticated quota;
- invalid auth does not debit a guessed valid credential bucket;
- process-local rate limiting is represented honestly and not claimed as cross-process/global enforcement.

### HTTPS production boundary

Verify production credential handling is fail-closed around external HTTPS:

- local development/test HTTP remains possible for deterministic tests;
- production does not accept externally insecure bearer traffic through an implicit/untrusted proxy assumption;
- trusted TLS termination/proto information cannot be spoofed by an untrusted direct peer;
- configuration is typed/bounded and does not echo private values;
- Node is not unnecessarily forced to become the public TLS terminator if a trusted upstream terminator is configured;
- deployment configuration does not make Cloudflare a mandatory application dependency.

If the final implementation relies only on operator promises while trusting arbitrary forwarded headers in code, treat that as a blocker.

### CORS and cache/security headers

Verify:

- no permissive browser CORS support was introduced;
- authenticated responses are not accidentally marked for public/shared caching;
- ETag/revalidation remains usable for the intended server-side client;
- existing safe Web headers remain intact;
- errors and successes use appropriate JSON content types where bodies exist;
- no response reflects credential/header details.

### Telemetry

Verify one bounded operational event exists for machine requests and can answer the required diagnostics without becoming analytics.

It may include Profile key, API version, status/outcome, duration, item/page facts, non-secret credential identity, auth/rate/missing/disabled/snapshot/dependency category, and bounded client version where implemented.

It MUST NOT include raw Authorization, bearer token fragments, verifier bytes, sensitive payloads, SQL/connection details, raw cursor payloads, arbitrary unbounded headers, click/referral/page-view/visitor identity, or backlink analytics.

Telemetry failure must not leak secrets or corrupt a successful response.

### Existing behavior

Verify Phase 4 preserves:

- `/` and `/api/feed` eligibility/public-status/discovery/ordering/destination behavior;
- admin enablement, Cloudflare perimeter assumptions, mutation integrity, and machine/admin separation;
- Phase 1 Profile administration;
- Phase 2 canonical read semantics;
- Phase 3 credential administration/authentication;
- collection/Worker behavior;
- idempotency, provenance, duplicate suppression, exact original publisher destinations, and topic independence.

No schema/migration change is expected. If one exists, stop and reconcile why before claiming closeout green.

## Pass 2 — Error and edge-case adversarial review

Independently derive realistic failures/attacks from the final implementation. Do not merely enumerate existing test names.

At minimum inspect:

### HTTP grammar and compatibility

- encoded/path-decoding edge cases in Profile key;
- unknown/repeated cursor parameters;
- malformed percent-encoding;
- oversized query/path/header values;
- request with arbitrary selector parameters;
- missing/combined/multiple Authorization header representation;
- wrong methods and unexpected body/cookies;
- invalid cursor for another Profile;
- malformed/tampered/current-revision-invalid-position cursor;
- exact page boundary, empty output, nullable metadata, unusual safe text;
- accidental omission of nullable or empty fields;
- generatedAt invalid clock/date;
- internal object spreading leaking IDs/state.

### Conditional requests

- matching/nonmatching `If-None-Match`;
- weak/list/wildcard or malformed forms according to final supported HTTP policy;
- conditional request with missing/draft/disabled Profile;
- conditional request with invalid/revoked credential;
- conditional request after rate limit;
- conditional header on a cursor request;
- snapshot mutation between requests;
- ETag formatting/quoting mistakes;
- accidental `304` with a JSON body.

### Auth/rate/trust attacks

- spoofed `X-Forwarded-For`, `Forwarded`, proxy-specific IP headers, or proto headers from an untrusted direct peer;
- malformed IPv4/IPv6/mapped-address values;
- trusted-proxy chain ambiguity/multiple hops;
- no immediate peer address or unusable request network state;
- invalid-auth flood from one versus many network keys;
- route accidentally reconstructing limiter/guard per request;
- process config reconstructed per request;
- one credential starving another;
- revoked/expired token distinctions leaking through status/body/timing structure beyond the Phase 3 bounded model;
- valid bearer reaching Profile read before auth/rate decision;
- Profile existence/lifecycle oracle exposed before authentication.

### HTTPS/deployment edge cases

- production with missing trust/TLS configuration;
- untrusted client supplying `X-Forwarded-Proto: https`;
- trusted terminator supplying expected secure context;
- local test/development HTTP behavior;
- direct origin bypass assumptions accidentally becoming part of machine authentication;
- startup errors echoing environment/header values;
- provider-specific config becoming mandatory contrary to self-hostability direction.

### Telemetry leakage/failure

- token/header fragments in events on `401`/`429`/`503`;
- verifier/internal credential object spread;
- cursor payload or Article body logged;
- SQL/connection error propagated into telemetry;
- unbounded User-Agent/client-version/header values;
- telemetry sink throws or blocks response path;
- request duration clock failure;
- duplicate/missing events on early failures;
- visitor/click analytics accidentally added.

### Preserved-surface regressions

- `/api/feed` status/schema changed by shared middleware;
- root SSR/reference UI altered by route registration/security config;
- admin routes begin accepting machine bearer identity;
- admin disabled state changes machine API semantics incorrectly;
- global Express proxy setting changes unrelated admin/public client-IP/security behavior unexpectedly;
- CORS/cache headers bleed onto unrelated surfaces.

For each plausible issue classify it as:

1. already protected by source structure + executed evidence;
2. bounded Phase 4 defect/test gap repairable inside closeout;
3. meaningful behavior-preserving refactor requiring the Terra High handoff below; or
4. contract/architecture/new-scope problem requiring stop/escalation/replanning.

A bounded repair is permitted only when behavior is already unambiguous under governing contracts and all invalidated evidence can be rerun.
