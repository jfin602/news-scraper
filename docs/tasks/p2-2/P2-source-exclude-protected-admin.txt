## Admin service/API behavior

Expose canonical Source state as separate bounded lists with unambiguous names such as:

- `rssAtomAdmissionIncludePhrases`;
- `rssAtomAdmissionExcludePhrases`.

Use the exact P1 normalized application boundary. The admin service/controller must not duplicate phrase trimming, count/length rules, or Include/Exclude precedence.

For create/update:

- omitted Exclude on legacy-compatible input means empty only where creation semantics require it;
- update semantics must distinguish omission from explicit empty according to the existing Source update contract so old clients do not accidentally erase managed lists;
- explicit empty list is the supported way to clear that side when the current admin mutation shape permits replacement;
- invalid list input returns the existing bounded validation response class without SQL/internal detail;
- Source audit/change history should truthfully capture Include/Exclude changes using the current bounded admin audit conventions, without storing unrelated secrets/raw request bodies.

Do not add an enabled toggle or `ANY/ALL` operator field.

## Protected browser UI

The Source create/edit experience must show clearly separated controls:

- **RSS/Atom Include phrases** — optional; empty means all items pass the Include side;
- **RSS/Atom Exclude phrases** — optional; any match rejects and Exclude wins.

Use the existing phrase-list interaction style if one exists. Keep the UI topic independent and concise. The browser should not implement filtering logic beyond shaping operator input; canonical validation remains server-side.

Requirements:

- load persisted Include and Exclude state correctly when switching/editing Sources;
- save both lists through the existing protected mutation route;
- clear either list intentionally;
- preserve the other list when only one is changed;
- prevent delayed Source A reads/mutations from painting Source B if current admin client already guards stale async state;
- preserve mobile/layout/accessibility conventions;
- do not expose operator selectors for `ANY/ALL`;
- do not imply this filter applies to HTML endpoints, Relevance, public search, or Profile filtering.
