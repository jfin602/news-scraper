## One package-owned env-file loader

Implement one bounded parser/loader owned by the PHP integration. It must support the documented simple `KEY=value` configuration shape needed by this package, reject malformed/ambiguous input clearly, avoid shell evaluation/interpolation, never execute PHP or expand commands, and not log secret values.

Do not import a general dotenv framework unless current PHP constraints make a small local parser unsafe.

The loader must distinguish:

### `local-read.env` — authoritative shared non-secret values

At minimum current shared values:

- Profile key;
- state root;
- sync cadence/freshness settings needed by both sync and local-read.

### `sync.env` — synchronization-only values

At minimum:

- upstream News Scraper base URL;
- bearer token;
- timeout/max-response/transport settings and other sync-only configuration.

Visitor/local-read code must not need to read `sync.env` and must not receive base URL/bearer values in its normalized config/result.

## Legacy duplicated shared keys

For upgrade compatibility only, legacy shared keys still present in `sync.env` may be accepted as validation aliases. When present:

- compare them against canonical `local-read.env` values using the same normalization expected by runtime configuration;
- exact semantic mismatch fails clearly before synchronization;
- matching aliases are ignored as authority;
- absence is preferred canonical state;
- never let `sync.env` override `local-read.env`.

Avoid an indefinite compatibility abstraction: keep alias handling narrow and explicit.

## Stable packaged sync launcher

Add source for root-level packaged `run-sync.php` (P4 will ensure package placement). It must:

- resolve sibling `../ns-private/local-read.env` and `../ns-private/sync.env` from the supported `ns-integration` layout without customer-specific absolute paths;
- load canonical configuration through the new package-owned loader;
- invoke the existing canonical sync runtime/`bin/sync.php` behavior, not duplicate synchronization logic;
- preserve supported `--force` semantics and existing exit/output behavior where contractually significant;
- keep bearer credentials out of command-line arguments, public HTML, and normal output;
- fail boundedly for missing/unreadable/malformed/mismatched config.

Do not add a second cron protocol or second synchronizer.

## Stable customer local-read entrypoint

Create one package-owned customer-facing entry file/API that hides internal `src/bootstrap.php`, source-file names, cache paths, generation manifests, and state layout.

The stable boundary should make ordinary customer code able to do conceptually:

```php
require <stable package entry>;
$result = <stable local-read operation using sibling ns-private/local-read.env>;
```

Exact filename/function/class shape is implementation-owned; prefer the smallest durable API. It must return the existing normalized `LocalReadResult` and preserve current state/freshness/digest semantics.

Customer code must not parse LKG files or instantiate internal state-store classes directly.

`src/bootstrap.php` may remain internal if still useful; it must cease being the documented customer dependency.
