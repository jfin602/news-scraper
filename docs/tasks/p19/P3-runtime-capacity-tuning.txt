GOAL
Establish an evidence-backed Phase 19 runtime policy for collection capacity, Worker timing, and delayed-health detection. The outcome may legitimately be that existing values remain unchanged if measurement supports them.

CURRENT AUTHORITIES TO PRESERVE
At planning time the implementation used PostgreSQL advisory slots for installation-wide global/Source/host capacity, held separately from the durable job lease and per-endpoint lock. Worker local concurrency is bounded by global capacity and the database pool reserves headroom for pinned capacity/endpoint-lock sessions plus persistence work.

Re-read source and preserve those conceptual separations:
- durable job lease = ownership of queued work;
- collection capacity = whether owned work may execute now;
- endpoint lock = same-endpoint exclusivity;
- endpoint health = derived observability, not lifecycle/operational state.

MEASUREMENT HARNESS
Create the smallest repeatable deterministic measurement/validation surface needed to assess current settings using controlled clocks/events and disposable PostgreSQL where cross-process behavior matters.

Measure representative scenarios such as:
- ready-job pickup delay under idle load;
- independent Sources/hosts progressing concurrently;
- one Source reaching its Source cap while another Source progresses;
- multiple Sources sharing one destination host reaching the host cap;
- aggregate global saturation;
- capacity-blocked job deferral and later reacquisition without retry-attempt consumption;
- database-pool headroom while the maximum permitted collection executions are active;
- scheduler pass/poll timing and health delayed-transition timing;
- recovery/lease timing relationships needed to avoid routine false stale ownership.

Use barriers/events and controlled clocks where possible. Do not make correctness assertions depend on arbitrary sleep races.

TUNING RULE
Do not change a constant just to show Phase 19 activity.

For every changed value:
- record the before value;
- record the measured behavior motivating the change;
- explain the intended operational effect;
- prove the changed value remains compatible with DB-pool headroom, lease/renewal relationships, and cross-process safety;
- update focused tests that encode legitimate policy values.

If current values remain appropriate, retain them and produce measurement evidence showing why.

Do not make capacity/environment configurable merely for flexibility unless actual deployment evidence establishes a need and all Worker processes can be guaranteed one coherent effective policy. Static named constants remain preferable to speculative configuration.

HEALTH TUNING
If delayed/unhealthy thresholds are considered:
- preserve existing five-state vocabulary;
- do not classify paused/disabled/archived resources as unhealthy;
- distinguish schedule delay from collection failure;
- avoid false delayed alerts during normal scheduler jitter/queue contention;
- require controlled evidence before changing threshold formulas.

CONCURRENCY / RATE-LIMIT BOUNDARY
The existing per-host capacity is the Phase 19 per-host rate/concurrency control authority unless evidence proves it insufficient.

Do not add:
- token buckets;
- another durable capacity table;
- process-local semaphores as cross-process authority;
- endpoint-specific throttlers;
- a second destination-host normalization/keying scheme;
- sleeps while holding durable claims merely to wait for capacity.

TESTS
Preserve and, where needed, strengthen Level 4 proof for:
- exact global/Source/host capacity across independent DB sessions;
- unrelated Source/host progress under saturation;
- blocked acquisition releasing partial slots;

Add measurement-output tests only where they protect reusable deterministic tooling; avoid brittle exact wall-clock performance assertions.
