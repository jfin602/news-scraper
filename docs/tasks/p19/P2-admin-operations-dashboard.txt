GOAL
Add an `Operations` workspace to the existing protected administration UI that makes current installation health and work backlog understandable at a glance while remaining a read-only presentation of P1's canonical operational snapshot.

BROWSER OWNERSHIP RULE
The browser may format, sort only when the API contract explicitly permits it, refresh, and navigate. It must not calculate or redefine:
- endpoint health;
- queue readiness/staleness;
- lease expiry or recovery status;
- alert severity/status;
- retry classification;
- collection-capacity policy.

If the browser needs a missing semantic field, add it to P1's backend boundary in the smallest compatible way with focused tests rather than reproducing domain logic in JavaScript.

UI CONTENT
Provide a clear operator-oriented workspace containing, as available from P1:
- overall operational status;
- endpoint counts by health;
- queue/running/ready-work summary;
- oldest ready-work delay;
- actionable delayed/degraded/unhealthy endpoints;
- relevant last success/failure/next due/cooldown details;
- current capacity/timing policy as informational facts;
- deterministic alert list;
- useful links/actions that navigate to existing Source/endpoint administration for diagnosis rather than duplicating those editors.

Keep the dashboard compact. Do not build a charting framework, historical time-series warehouse, or configurable alert editor in P2.

ADMIN INTEGRATION
- Extend the existing admin workspace navigation without regressing Publication, Sources, Editorial, or Articles.
- Reuse the existing protected admin API request helper and required request-integrity behavior where applicable.
- Operations is read-only; do not add mutation controls merely because the page shows problems.
- Use safe DOM/text APIs. Do not use untrusted Source/endpoint/error text as executable HTML.
- Preserve CSP and same-origin constraints.
- Make refresh behavior explicit and non-duplicative; avoid overlapping refresh requests causing stale state to overwrite newer state.
- Show bounded loading, empty, unavailable, and error states.
- Do not turn dependency failure into a false healthy state.

ACCESSIBILITY / RESPONSIVE
Preserve existing admin design guidance:
- keyboard-reachable navigation and controls;
- visible focus;
- meaningful headings and labels;
- live-region/status announcements that do not spam users;
- tables/cards that remain usable on narrow viewports without destructive horizontal overflow;
- status is not communicated by color alone.

BROWSER / INTEGRATION TESTS
Add focused HTTP/client tests and real Chromium coverage for:
- Operations workspace appears in navigation and can be selected;
- loading and healthy/empty states;
- delayed/degraded/unhealthy endpoint presentation;
- ready queue and oldest-delay presentation;
- alert rendering and safe hostile-text rendering;
- backend error/unavailable state and successful later refresh;
- stale/in-flight refresh does not overwrite newer state or duplicate requests materially;
- links/navigation to relevant Source/endpoint administration work;
- keyboard/focus/live-region behavior;
- representative mobile viewport containment;
- existing Publication/Sources/Editorial/Articles workspace navigation remains functional.

Do not make browser tests responsible for proving P1 SQL or health derivation; those are P1 tests.
