PASS 1 — CONTRACT / EVIDENCE
Validate the integrated final tree against the Phase 19 roadmap and governing contracts.

A. OPERATIONAL SNAPSHOT / ALERTS
Prove:
- one canonical server-side operational snapshot owns health/queue/alert semantics;
- endpoint health reuses canonical health derivation and does not confuse lifecycle/operational state with health;
- ready/future/running jobs and oldest-ready delay are truthful;
- alert/status derivation is deterministic, bounded, topic independent, and non-authoritative;
- snapshot reads do not mutate jobs/endpoints/runs;
- database failure cannot become fabricated green state;
- no unbounded/N+1 query behavior exists at intended MVP scale;
- protected admin API exposes only bounded non-secret operational facts.

B. ADMIN OPERATIONS DASHBOARD — LEVEL 6
Observe in Chromium:
- Operations workspace loads and navigates correctly;
- healthy/empty, delayed/degraded/unhealthy, queue-delay, and backend-error/recovery states render truthfully;
- hostile Source/endpoint/error text remains inert;
- refresh does not create stale overwrite/duplicate-request behavior;
- keyboard/focus/live-region/mobile behavior is usable;
- links navigate to existing Source/endpoint administration rather than duplicating authority;
- Publication/Sources/Editorial/Articles workspaces remain functional;
- browser does not implement health/queue/alert calculations.

C. RUNTIME / CAPACITY TUNING — LEVEL 4
Confirm:
- measurement procedure is repeatable and records the evidence used for final values;
- existing global/Source/host cross-process authority remains coherent;
- unrelated Source/host work progresses under localized saturation;
- blocked capacity defers safely without retry/run consumption;
- endpoint lock remains independent;
- DB-pool headroom is sufficient for selected global capacity;
- Worker lease/renewal/recovery timing relationships are valid;
- delayed-health behavior avoids normal-jitter false positives;
- values were not changed merely for ceremony; unchanged values are justified by evidence;
- no second semaphore/rate-limit/lease architecture exists.

D. SECURITY / ABUSE
Run and inspect the specialized security evidence. Confirm adversarial coverage for:
- Source/endpoint approval and state gating;
- scheme/domain/port/DNS/address SSRF policy including special-use and mapped-address cases;
- redirect revalidation and validated-address transport binding;
- fetch/response/decompression/parser bounds;
- RSS/HTML media-type isolation;
- static HTML no-subresource/no-Article-page/no-browser-fetch behavior;
- preview no-network/no-persistence behavior;
- inert public/admin content;
- admin request integrity, body/JSON bounds, and real resource relationships;
- CSP/error/secret leakage;
- Web/Worker structured failure diagnostics.

Do not count real Cloudflare Access proof here; that is Section G.

E. BACKUP / RESTORE / RETENTION — LEVEL 4
Using real PostgreSQL/native tooling, prove:
- backup command fails clearly if prerequisites are absent and never logs credentials;
- failed/interrupted backup is not represented as valid completed backup;
- restore defaults to a safe explicit fresh target rather than silently replacing current DB;
- representative Publication/Source/endpoint/Category/Relevance/Article/observation/run/job/duplicate/moderation/history state survives semantically;
- restored repositories/services can read expected state;
- queued/expired/in-flight job/run recovery follows existing semantics without unsafe duplicate replay;
- corrupt/incompatible restore fails closed;
- retention pruning only deletes managed eligible backup artifacts and invalid policy deletes nothing;
- actual backup/restore duration evidence is recorded where measurable.

F. SCHEMA UPGRADE / ROLLBACK / DEPLOYMENT PROCEDURE
Prove:
- schema status/preflight distinguishes uninitialized/current/pending/incompatible safely;
- representative earlier pre-launch DB state upgrades through actual migration files to current;
- seeded governed data/relationships survive;
- application reads/writes work after upgrade;
- pre-upgrade backup permits safe rollback/restore when in-place schema reversal is unsupported;
- the test/evidence explicitly does not promote arbitrary old pre-production DBs to supported production inputs;
- deployment procedure identifies exact source/version, backup, preflight, migration, Web/Worker startup/readiness, smoke checks, operational verification, and rollback decision points;
- required incident runbooks point to real commands/controls and do not invent capabilities.

PASS 2 — ERROR / EDGE-CASE ADVERSARIAL REVIEW
After Pass 1 is green on a candidate tree, independently derive realistic failure hypotheses from the actual implementation rather than existing test names.

At minimum challenge:
- operational snapshot during empty DB, all-paused Sources, queued-only backlog, expired-running jobs, DB interruption, and clock-boundary cases;
- alert severity/order with simultaneous health and queue problems;
- stale/out-of-order dashboard refresh response;
- capacity saturation plus scheduler/recovery activity and DB-pool exhaustion pressure;
- worker shutdown while capacity/job/lease work is active;
- security suite blind spots created by shared helper assumptions;
- backup destination collision, partial file, disk/path error, symlink/foreign file, tool absence, wrong DB target, corrupt archive, restore failure, and cleanup failure;
- secrets embedded in intentionally hostile connection/path/tool stderr sentinels;
- restore containing queued/running/expired jobs and interrupted Collection runs in combinations not covered by normal tests;
- migration checksum mismatch, missing repository migration, partial migration failure, concurrent migration attempt, and application rollback against an incompatible upgraded schema;
- deployment failure after backup but before migration, during migration, after migration before Worker start, and after Web start before operational verification;
- Cloudflare Access lockout where public feed remains healthy;
- origin exposure by alternate port/hostname/IP or deployment misconfiguration;
- redirect behavior during unauthenticated admin probe that could be mistaken for application success;
- authorized admin session succeeding only because direct origin was used rather than Access path;
- monitoring ownership missing when an alert is intentionally induced;
- restore/RPO/RTO claims not matching actually observed procedure/duration;
- artifact accidentally containing secret-bearing URLs/tokens/cookies;
- Phase 19 wording accidentally declaring the Phase 20 production baseline early.

Classify each finding:
1. protected by implementation plus meaningful observed evidence;
2. clear governed behavior but weak coverage — add bounded regression/evidence;
3. concrete bounded Phase 19 defect — repair and rerun invalidated evidence;
4. meaningful behavior-preserving refactor — stop and emit Terra High remediation prompt;
5. material ambiguity/hard defect — stop for model escalation/replanning/correction.
