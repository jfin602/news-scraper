PRODUCTION MIGRATION

TABLE: publications
Persist only:
- `id uuid PRIMARY KEY`;
- `name text NOT NULL`;
- `slug text NOT NULL`;
- `active_for_collection boolean NOT NULL`;
- `public_status text NOT NULL`;
- `created_at timestamptz NOT NULL DEFAULT now()`;
- `updated_at timestamptz NOT NULL DEFAULT now()`.

Required constraints:
- unique `slug`;
- name is nonblank after trim and reasonably bounded;
- slug uses a canonical lowercase hyphenated shape such as `[a-z0-9]+(-[a-z0-9]+)*` and is reasonably bounded;
- `public_status` accepts only the minimal Phase 3 values `private` and `public`.

Do not add description, timezone, branding, feed settings, Categories, Relevance fields, or other future Publication fields.

TABLE: sources
Persist only:
- `id uuid PRIMARY KEY`;
- `publication_id uuid NOT NULL`;
- `config_key text NOT NULL`;
- `display_name text NOT NULL`;
- `site_url text NOT NULL`;
- `approval_state text NOT NULL`;
- `lifecycle_state text NOT NULL`;
- `operational_state text NOT NULL`;
- `created_at timestamptz NOT NULL DEFAULT now()`;
- `updated_at timestamptz NOT NULL DEFAULT now()`.

Required constraints:
- FK to `publications(id)`;
- `UNIQUE (publication_id, config_key)`;
- config key canonical lowercase underscore shape such as `[a-z0-9]+(_[a-z0-9]+)*` and reasonably bounded;
- display name nonblank and reasonably bounded;
- site URL nonblank and reasonably bounded at SQL level; full URL semantics belong to P2;
- approval state only `approved` / `unapproved`;
- lifecycle state only `active` / `archived`;
- operational state only `enabled` / `paused` / `disabled`.

Do not add Source priority, default Category, Relevance settings, health, collection timing, or parser fields.

TABLE: source_approved_domain_rules
Represent Source maximum approved-domain policy relationally rather than as a JSON blob or wildcard string.

Persist:
- `source_id uuid NOT NULL`;
- `hostname text NOT NULL`;
- `include_subdomains boolean NOT NULL DEFAULT false`.

Required constraints:
- FK to `sources(id)`;
- one logical rule per normalized hostname for a Source, recommended `UNIQUE (source_id, hostname)`;
- hostname nonblank, lowercase, no surrounding whitespace, and reasonably bounded at SQL level.

P1 should enforce cheap persisted-shape invariants only. Full DNS-hostname normalization and hierarchy semantics belong to P2. Do not parse schemes/paths or implement suffix hierarchy through SQL triggers.

TABLE: source_endpoints
Persist only:
- `id uuid PRIMARY KEY`;
- `source_id uuid NOT NULL`;
- `config_key text NOT NULL`;
- `endpoint_url text NOT NULL`;
- `endpoint_type text NOT NULL`;
- `approval_state text NOT NULL`;
- `lifecycle_state text NOT NULL`;
- `operational_state text NOT NULL`;
- `poll_interval_seconds integer NOT NULL`;
- `created_at timestamptz NOT NULL DEFAULT now()`;
- `updated_at timestamptz NOT NULL DEFAULT now()`.

Required constraints:
- FK to `sources(id)`;
- `UNIQUE (source_id, config_key)`;
- `UNIQUE (source_id, endpoint_url)`;
- config key canonical lowercase underscore shape and reasonably bounded;
- endpoint URL nonblank and reasonably bounded at SQL level; structural URL/domain semantics belong to P2;
- endpoint type only `rss_atom`;
- approval/lifecycle/operational vocabularies match Source state vocabularies;
- polling bound exactly `60 <= poll_interval_seconds <= 2592000`.

The endpoint URL must NOT be globally unique. The same URL may be configured under another independent Source/Publication later. Stable bootstrap identity is `config_key`, not URL.

TABLE: source_endpoint_domain_rules
Represent optional endpoint narrowing relationally.

Persist:
- `source_endpoint_id uuid NOT NULL`;
- `hostname text NOT NULL`;
- `include_subdomains boolean NOT NULL DEFAULT false`.

Required constraints:
- FK to `source_endpoints(id)`;
- `UNIQUE (source_endpoint_id, hostname)`;
- same basic lowercase/nonblank/bounded persisted-host shape as Source domain rules.

Zero endpoint-domain-rule rows means inherit the Source maximum policy. P1 must not attempt cross-table hostname hierarchy enforcement; P2/P3 own semantic validation before writes.

FOREIGN-KEY / DELETE BEHAVIOR
Choose conservative referential behavior consistent with lifecycle-based retirement. Do not introduce broad cascading deletion semantics merely for convenience. Child domain-policy rows may use tightly scoped cascade behavior if justified, but deleting a Publication/Source should not silently erase large configuration trees unless an explicit contract requires it.

DATABASE VERSUS APPLICATION AUTHORITY
Use PostgreSQL constraints for invariants PostgreSQL can prove directly:
- parent ownership;
- stable-key uniqueness;
- endpoint URL uniqueness within Source;
- state vocabularies;
- endpoint type;
- polling numeric bounds;
- basic canonical key/host persisted shape.

Do NOT use SQL triggers/functions for:
- DNS suffix/subdomain hierarchy;
- endpoint hostname membership in Source policy;
- endpoint policy narrowing;
- runtime collectability;
- archive/restore transitions;
- network safety.

Those semantics belong in later TypeScript configuration/eligibility layers.
