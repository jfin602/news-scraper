GOAL
Expose the P1 singleton Publication presentation values through the one canonical public-feed read model and `GET /api/feed` response:
- required `name`;
- nullable `description`;
- nullable `logoPath`;
- nullable `accentColor`.

P2 is intentionally backend/read-model only. It must not implement branding DOM, theme controls, CSS redesign, or the R7KM loading fix.

PUBLIC READ MODEL
Extend `PublicFeedPublication` to require the canonical public presentation shape:
- `name: string`;
- `description: string | null`;
- `logoPath: string | null`;
- `accentColor: string | null`.

Do not make the new fields optional properties merely to ease fixture migration. A public Publication response has a stable explicit shape; missing persisted optional values are represented by JSON `null`.

Do not expose:
- `activeForCollection`;
- `publicStatus`;
- timestamps;
- internal Publication identity/slug/tenant fields;
- raw CSS or HTML;
- admin-only state.

REPOSITORY QUERY + MAPPING
Extend the existing public Publication query to select only the four required public presentation values from the singleton `publication_settings` row when `public_status = 'public'`.

Keep the existing public-state behavior:
- absent Publication -> no public feed;
- private Publication -> no public feed;
- public Publication -> bounded read model.

Preserve the existing second/final public Publication read in `readPublicFeed()` unless a higher-authority current contract or observed implementation change demonstrates it is obsolete. Do not opportunistically simplify public-state race protection while changing presentation fields.

Map values defensively:
- required name remains trimmed/non-empty;
- nullable values must be either null or already-valid canonical strings consistent with P1 persistence;
- malformed/corrupt database values must become the existing bounded `PublicFeedRepositoryError('invalid_row')` behavior rather than leak raw data or be repaired into a different value.

Do not duplicate a full second presentation-validation subsystem if P1 exposes narrowly reusable canonical helpers. Reuse where it keeps one source of truth without coupling the public-feed repository to bootstrap behavior.
