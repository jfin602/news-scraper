GOAL
Apply the approved Phase 13 `modern editorial / publication desk` visual specification to the canonical root feed and complete the in-scope responsive/accessibility presentation pass without changing feed/discovery semantics.

The Publication and headlines are the product. Keep the presentation restrained and editorial rather than turning the page into a generic SaaS dashboard, card portal, sidebar application, glassmorphism layout, heavy-shadow composition, decorative-gradient interface, or zebra table.

APPROVED COMPOSITION
Use a centered editorial canvas in the established ~70–76rem range with responsive side padding.

Vertical order:
1. Publication masthead;
2. discovery/filter band;
3. feed status/state region;
4. headline feed;
5. local load-more controls.

The masthead should present configured logo/name/description and the secondary theme control with clear hierarchy. Missing logo/description must collapse naturally.

Use configured accent color only as a restrained brand signal such as a thin rule, mark, or selected-control detail. Never depend on arbitrary Publication accent for required text/focus/error contrast.

TYPOGRAPHY
Use dependency-free local/system stacks only.

Presentation hierarchy:
- serif-forward stack for Publication name and Article headlines;
- neutral sans-serif stack for dates, Source names, discovery controls, theme controls, buttons, statuses, and pagination.

Do not add remote font dependencies or build/font tooling.

DESKTOP FEED
Keep the customer-required three-column concept:
`Date | Headline | Source`

Style it as a news index rather than a spreadsheet:
- narrow muted Date column;
- dominant flexible Headline column;
- medium muted Source column;
- thin separators;
- comfortable vertical rhythm;
- understated column headings;
- no Article cards;
- no zebra striping;
- no destructive truncation;
- headline remains the dominant interactive element with clear link/hover/focus affordance.

MOBILE FEED + LOGICAL ORDER
The approved mobile pattern is:
`DATE · SOURCE`
`Linked article headline`

Make the DOM/logical reading order compatible with this mobile presentation. If the current row order is Date -> Headline -> Source, refactor the row children to a logical order such as Date -> Source -> Headline, then use desktop CSS grid areas/order to visually restore Date | Headline | Source.

Do not create a CSS-only visual ordering that leaves keyboard/screen-reader reading order materially inconsistent with the mobile visual order.

Rows remain rule-separated, not card-based.

DISCOVERY BAND
Preserve the exact keyword/Source/Category/Search/Reset behavior from Phase 12 while presenting it as one compact editorial filter band.

Desktop target:
`[ Keyword........ ] [ Source ▾ ] [ Category ▾ ] [ Search ] [ Reset ]`

Requirements:
- Search is visually primary;
- Reset is quiet/secondary but easy to locate, especially for invalid discovery state;
- consistent control height;
- subtle border/surface differentiation;
- modest radius, not pill-heavy styling;
- clear labels and visible focus;
- controls reflow before becoming cramped;
- long selected Source/Category values cannot force horizontal page overflow.

THEME CONTROL
Finish the P4 System/Light/Dark control styling using the approved compact secondary treatment. All three states remain explicit; do not reduce behavior to a binary toggle.

Keep the same semantic/native control behavior established in P4. Styling must not replace native semantics with a custom keyboard model.

LIGHT/DARK DESIGN TOKENS
Complete the semantic token values established in P4.

Light direction:
- warm/off-white page;
- dark charcoal primary text;
- restrained gray metadata/rules;
- subtly differentiated filter/control surfaces;
- sparse brand accent.

Dark direction:
- deep charcoal rather than pure black;
- soft off-white primary text;
- readable muted metadata;
- subtle but perceivable surface/rule differentiation;
- sparse brand accent.

Keep application-owned safe values for body text, muted text, link, focus, error, border, and control states. Do not dynamically derive contrast-critical text from arbitrary `accentColor` unless a deterministic, tested safe fallback exists; the simplest correct Phase 13 design is to reserve accent for noncritical decorative/selected details.

ACCESSIBILITY TARGET
The in-scope root feed targets WCAG 2.2 Level AA presentation behavior.

At minimum ensure:
- native/semantic interactive controls;
- coherent keyboard focus order;
- no keyboard trap;
- unmistakable `:focus-visible` indication in both themes;
- applicable text/control/focus contrast in both themes;
- controls meet the applicable WCAG 2.2 target-size requirement or a permitted spacing exception;
- statuses/loading/errors are understandable to assistive technology and do not rely only on color;
- long content reflows without horizontal page scrolling at supported widths;
- motion honors `prefers-reduced-motion`.

Do not make broad conformance claims from visual inspection alone. Add concrete automated assertions for the behaviors this codebase can deterministically prove and leave P6 to synthesize final-tree evidence.

FOCUS / CONTROL STATES
Style at least:
- headline links;
- keyword input;
- Source/Category selects;
- Search;
- Reset;
- System/Light/Dark controls;
- Load more.

Each must have a clear keyboard focus indicator in both effective themes. Disabled/busy Load more remains distinguishable without relying only on opacity/color.

LOADING / STATES
Preserve P3's neutral initial loading lifecycle and improve its presentation:
- centered intentional loader/status;
- no fake/skeleton headlines;
- no generic Publication placeholder;
- reduced-motion users receive an equivalent static/non-continuous indication.

Empty, invalid, unavailable, dependency-error, and continuation-error states should use restrained consistent typography/spacing in the feed region rather than giant alert cards.

Continuation error remains local to pagination and never destroys loaded Articles. Load more should retain stable footprint while busy and keep local progress/error messaging.

MOTION
Keep motion minimal:
- short color/background/focus transitions are acceptable;
- lightweight loader rotation is acceptable only for users who have not requested reduced motion;
- avoid row entrance animations, theme crossfades, sliding filter panels, parallax, and animated headline reflow.

Under `prefers-reduced-motion: reduce`, remove nonessential transitions/continuous loader animation while keeping the loading state understandable.

RESPONSIVE / LONG-CONTENT BEHAVIOR
Browser-test representative desktop and mobile widths plus long-content stress cases.

Required outcomes:
- no horizontal document scrolling;
- long headlines wrap naturally;
- long Source names wrap/contain without colliding with headline/date;
- long Category/Source select values remain usable;
- discovery controls collapse to a natural one-column/full-width flow when required;
- desktop column headings disappear appropriately on stacked mobile;
- mobile metadata renders Date · Source before the headline;
- no important control becomes clipped/off-screen;
- masthead/logo/description/theme controls reflow coherently.

EXTERNAL LINKS
Headline links remain ordinary anchors whose `href` is the exact stored `original_url` supplied by `/api/feed`.

Do not:
- force `target=_blank`;
- add redirect/tracking wrappers;
- replace destination with canonical identity URL;
- imply Platform authorship of linked content.

External navigation should be visually understandable while preserving normal same-context activation.

FOCUSED BROWSER TESTS — LEVEL 6
Extend the Playwright suite to prove at minimum:

Desktop:
- column headings and row placement are Date | Headline | Source;
- headline remains dominant and link is directly activatable;
- long content does not overlap or force horizontal page scrolling.

Mobile:
- column headings are not visually presented as a compressed table;
- metadata visual/DOM order is Date · Source then headline;
- discovery/theme controls are usable without overflow;
- long headline/source/category content wraps safely.

Themes:
- representative light and dark computed page/text/control/focus values are distinct and readable;
- explicit P4 selection/persistence/system-following tests remain green;
- Publication accent does not replace the safe focus/error/body-text token.

Keyboard/focus:
- focus traversal reaches discovery, theme, headline and load-more controls in coherent order;
- each important control has a visible computed focus indication in both themes;
- no keyboard trap.

Target sizing:
- primary controls and links satisfy the chosen deterministic target-size/spacing assertions at representative desktop/mobile widths.

Reduced motion:
- emulated reduced-motion preference removes continuous loader animation/nonessential transitions while status text remains present.

States:
- loading, empty, invalid, unavailable, dependency error, continuation loading/error remain distinct and readable;
- invalid state keeps Reset accessible;
- continuation error preserves rows;
- busy Load more keeps local status and stable usable control layout.

Preservation:
- direct URL, refresh, Search, Reset, Back/Forward and load-more workflows remain green;
- stale first-page/continuation tests remain green;
- UTC dates remain unchanged;
- exact original publisher links remain same-context;
- untrusted Publication/Source/Category/headline text remains inert.
