CORRECTION GOAL
The existing Profile **AI digest** admin section must expose one simple optional writing-style field backed directly by P1's protected configuration representation:

```text
Digest writing style
[ textarea ]
Optional; blank uses the default digest writing style.
Up to 500 Unicode code points.
```

An administrator should be able to load a Profile, see its current guidance, edit/save it alongside the existing digest settings, switch Profiles without stale AI state leaking across selections, and use Generate now separately through the unchanged generation action.

ADMIN HTML
In the existing Profile AI digest configuration form in `src/app/web/admin-page.ts`:
- add an accessible label exactly/clearly identifying **Digest writing style**;
- use a plain `<textarea name="digestStyleGuidance">` suitable for a short instruction, preferably reusing existing wide-field/form styling rather than introducing a new presentation system;
- helper text must communicate that the field is optional, blank uses normal/default digest writing style, and the server limit is 500 Unicode code points;
- do not describe it as a system prompt, developer prompt, arbitrary instructions, or URL input;
- do not expose Gemini keys, model selectors, tool controls, raw prompts, or provider diagnostics;
- preserve the current AI cadence/status/Generate-now UI and existing admin presentation conventions.

Do **not** use HTML `maxlength="500"` unless you also prove it counts the contract's Unicode code points correctly. Browser maxlength semantics are based on UTF-16 code units and can incorrectly reject a valid 500-code-point astral/emoji value. Prefer server-authoritative validation and clear helper text over a subtly wrong native limit. Do not build a duplicate client normalization framework merely to enforce the server rule.

ADMIN CLIENT DATA FLOW
In `src/app/web/admin/profiles.js`:
- when AI state loads, populate the textarea from `ai.configuration.digestStyleGuidance ?? ''`;
- when saving AI configuration, send `digestStyleGuidance` explicitly with the existing `digestEnabled`, `lookbackDays`, and `maxArticles` body;
- blank textarea input is sent as blank text; P1's server normalizer owns blank→null canonicalization;
- after a successful save, render the returned canonical server state rather than assuming the typed value is canonical;
- preserve the existing status message that the next scheduled evaluation uses saved settings; saving still does not call Generate now automatically;
- preserve separate manual **Generate now** behavior;
- preserve stale-response protection: a delayed AI response/save for Profile A must not repaint Profile B after the operator switches selection;
- do not copy prompt composition, URL neutralization, identity hashing, or 500-code-point normalization into browser code;
- never place guidance in URLs/query strings/local storage or public page state; it travels only through the existing protected JSON admin request.

ERROR / BOUNDARY BEHAVIOR
- existing bounded `invalid_request` handling remains the error surface for invalid/over-limit guidance;
- a rejected save leaves the selected Profile/editor state usable and does not trigger generation;
- a successful clear displays an empty textarea after the canonical response returns null;
- saving one Profile must not mutate another Profile's guidance;
- ordinary Profile configuration, Source associations, lifecycle controls, and AI status continue to work unchanged;
- the browser must not render guidance as HTML/Markdown; it is only a textarea value.
