CONTEXT
P7 successfully split the former monolithic admin browser client into native ES modules with canonical ownership:
- `admin.js` coordinates workspace activation, tabs/panels, Refresh All, and Operations -> Sources navigation;
- `core.js` owns shared API/mutation/status/DOM helpers;
- `catalog.js` owns shared Source/Category choice state;
- `publication.js`, `operations.js`, `sources.js`, `editorial.js`, and `moderation.js` own workspace behavior.

The post-P7 optimization reassessment found that the workspace split is incomplete at the local ownership level. Each workspace still carries a copied all-admin `elements` registry and broad helper imports inherited from the original monolith. The five files suppress `@typescript-eslint/no-unused-vars`, hiding hundreds of irrelevant selectors/imports and making every workspace depend on unrelated workspace markup at module load.

GOAL
Complete the P7 ownership split without redesigning the browser application:
- each workspace queries only the DOM it actually owns/uses;
- each workspace imports only helpers/state it actually consumes;
- remove the broad unused-variable lint suppressions;
- preserve coordinator/core/catalog responsibilities and every existing admin behavior.

PRIMARY FILES
Expected production scope:
- `src/app/web/admin/publication.js`
- `src/app/web/admin/operations.js`
- `src/app/web/admin/sources.js`
- `src/app/web/admin/editorial.js`
- `src/app/web/admin/moderation.js`

Tests may be updated/added under the existing admin browser/unit/integration suites when needed for focused proof. Touch `admin.js`, `core.js`, or `catalog.js` only if source inspection proves a small correction is necessary to preserve the already-established ownership model. Do not broaden into another module redesign.

IMPLEMENTATION REQUIREMENTS
1. For each workspace, shrink its `elements` object to selectors actually consumed by that workspace.
2. Coordinator-owned tabs/panels remain in `admin.js`; do not reintroduce them into workspace registries.
3. Publication keeps only Publication form/state/error/timezone and other directly used Publication controls.
4. Operations keeps only Operations snapshot/state/summary/health/queue/endpoints/alerts/policy/refresh controls it actually consumes.
5. Sources keeps only Source/endpoint/domain/profile/preview/runtime/health/run/check-now controls it actually consumes.
6. Editorial keeps only Category/Relevance controls it actually consumes.
7. Moderation keeps only Article/duplicate-review/filter/detail/mutation controls it actually consumes.
8. Shrink each `core.js` import list to actual consumers. Remove unused `catalog` imports where a workspace does not use the catalog.
9. Remove `/* eslint-disable @typescript-eslint/no-unused-vars */` from all five workspace modules. Do not replace it with another broad lint suppression.
10. If a workspace repeatedly calls `required(...)` for one of its own stable controls, it MAY place that handle in its local `elements` object when that makes ownership clearer. This is local cleanup only.
11. Do not create a generic selector registry, dependency-injection layer, component framework, bundler, build step, or compatibility global to replace the removed duplication.
