GOAL
Turn `admin-router.ts` into a thin composition boundary by separating:
- admin page/template + explicit static asset serving; and
- security-critical admin API middleware/integrity/error handling.

CURRENT PROBLEM
At planning time one large module owns the complete admin HTML template, CSS/JS file loading and page routes, CSP/security headers, mutation request-integrity enforcement, JSON body parsing, nested duplicate-key rejection, and generic API error shaping. Security-critical code is therefore structurally buried inside a presentation-heavy module and P7 cannot add native browser modules without touching that same file.

TARGET OWNERSHIP
Prefer three clear responsibilities, with exact filenames allowed to vary when a nearby existing convention is better:

1. `admin-router.ts`
   - thin exported composition entry points such as `createAdminPageRouter`, `createAdminApiRouter`, and route-registrar typing;
   - no giant inline HTML document;
   - no private implementation of duplicate-key parsing or mutation-integrity policy.

2. an admin API security module, e.g. `admin-api-security.ts`
   - common admin security headers where appropriate;
   - unsafe-method mutation-integrity header enforcement;
   - JSON content-type/body-size parser;
   - nested duplicate JSON object-key rejection;
   - bounded generic parser/handler error response behavior;
   - canonical exported header constants used by tests/clients where a server-owned constant is appropriate.

3. an admin page/static module, e.g. `admin-page.ts`
   - HTML document/template;
   - explicit allowlisted static asset definitions/content/media types;
   - page/static route registration or equivalent page-serving primitive.

Do not over-fragment into many one-function files.

STATIC-ASSET SECURITY BOUNDARY
The admin asset surface must remain explicitly allowlisted.

Do NOT replace the current finite routes with unrestricted `express.static()` over a source directory, arbitrary user/path-derived filesystem reads, directory traversal-capable routing, or a wildcard that exposes other repository files.

P6 should leave a small explicit asset manifest/route mechanism that P7 can extend with additional same-origin JS module files without modifying API security middleware. At P6 completion it need only serve the current CSS and entry JS plus whatever minimal structure is necessary for that later handoff.

Preserve correct content types, no-store/security headers, disabled-admin routing behavior, and same-origin CSP semantics.

REQUEST INTEGRITY / ERROR PRESERVATION
Preserve exactly:
- unsafe admin methods require the canonical request-integrity header/value;
- unsafe requests require `application/json` where currently required;
- body size remains bounded;
- nested duplicate JSON object keys are rejected before handler mutation;
- malformed JSON is bounded `400` behavior;
- missing integrity is bounded `403` behavior;
- wrong content type is bounded `415` behavior;
- oversized body retains established bounded behavior;
- unhandled handler/dependency errors remain generic and do not leak SQL, stack traces, database URLs, secrets, or private details;
- GET/read-only admin routes retain their intended behavior;
- Cloudflare Access remains the external perimeter and direct-origin policy is unchanged.

Do not move service/domain validation into the security module; P5 owns shared structural service validation and domain services remain authoritative.

DOWNSTREAM HANDOFF TO P7
P7 must be able to add multiple native browser module assets without editing security middleware.

Required handoff:

`admin page HTML -> explicit entry script route -> page/static asset owner`

`relative same-origin module import such as ./core.js -> explicit allowlisted /admin/assets/core.js -> correct JavaScript media type/security headers`

`admin API mutation -> admin API security owner -> integrity/content/duplicate-key checks -> registered API handler`

Add focused tests proving the first and third relationships now, and structure the asset manifest so P7 can extend the second without a security-module edit. Do not add fake placeholder module files before P7.
