Phase 7 is green only when observed evidence against the exact accepted tree proves:
1. every safe candidate passes Relevance before identity;

PHASE 7 BEHAVIOR EVIDENCE MATRIX
The closeout artifact must identify concrete tests/commands proving each area below.

A. RELEVANCE ORDERING / DEFAULT INCLUDE — LEVELS 2/3/5
Prove:
- P1 deterministic empty-rule evaluator returns include;
- canonical Worker ordering invokes Article-link policy before Relevance and Relevance before Article identity;
- link-rejected candidates do not invoke Relevance/identity;
- production Phase 7 integrated runs have `excluded_count = 0`;
- behavior remains generic across unrelated Publication/Source data.

B. STRONG EXTERNAL-ID IDENTITY — LEVEL 4
Prove:
- same Source strong external ID resolves one Article;
- URL/source-derived metadata may change without creating a new Article;
- same strong ID in another Source remains separate;
- full stored identity is verified rather than digest equality alone.

C. CANONICAL FALLBACK / PROMOTION / CONFLICT — LEVEL 4
Prove:
- canonical-only candidate creates/reuses one fallback Article;
- canonical-only candidate can resolve one existing strong-ID Article by exact canonical URL;
- fallback -> strong-ID promotion preserves Article cardinality when no contradictory strong identity exists;
- different strong IDs sharing one canonical URL remain separate;
- canonical-only ambiguity across multiple different strong IDs is an explicit failure and does not choose arbitrarily;
- fuzzy/normalized-title similarity does not resolve identity.

D. IDEMPOTENT CREATE / UPDATE / UNCHANGED — LEVEL 4
Prove:
- first observation `created`;
- repeated unchanged observation `unchanged` and no cardinality growth;
- material Source-derived change `updated`;
- last-seen/observation updates alone do not become `updated`;
- first/last-seen semantics remain correct under deterministic replay times.

E. CONCURRENT/RACING UNIQUENESS — LEVEL 4
Using independent actors + deterministic barriers, prove:
- same strong-ID race => one Article;
- same canonical-only race => one fallback Article;
- strong-ID versus canonical-only race => one logical Article with strong ID attached;
- two different strong IDs on same canonical URL => two Articles, never a merge;
- no timing-only sleep test is treated as proof of contention.

F. OBSERVATION PROVENANCE / OWNERSHIP — LEVEL 4
Prove:
- successful observations reference actual Article, Publication, Source, endpoint, and Collection run;
- run belongs to endpoint;
- endpoint belongs to Source;
- Source belongs to Publication;
- wrong cross-owner combinations are rejected;
- repeated observations retain distinct run provenance.

G. ARTICLE + OBSERVATION ATOMICITY / ROLLBACK — LEVEL 4
Prove:
- observation insertion failure rolls back Article creation;
- observation insertion failure rolls back material update/promotion;
- failed identity conflict commits no successful observation;
- transaction failure leaves database invariants intact.

H. UNRELATED-CANDIDATE ISOLATION — LEVELS 3/4
Prove:
- expected item-level identity conflict produces candidate `failed` outcome but does not erase/stop unrelated safely processable candidates;
- a stage-level persistence/Relevance failure stops unsafe remaining work but preserves already committed Articles/observations;
- no feed-batch-wide Article transaction exists.

I. COLLECTION-RUN OUTCOME ACCOUNTING — LEVELS 3/4/5
Prove for processing-attempted runs:

`created + updated + unchanged + rejected + excluded + failed = normalized_candidate_count`

Also prove:
- normalization failures stay outside the processing equation;
- Article-link rejections remain counted in `article_link_rejection_count` and map to processing `rejected`;
- production Phase 7 behavior has `rejected_count == article_link_rejection_count` and `excluded_count == 0`;
- ordinary candidate failures may coexist with `processing_status = succeeded`;
- stage-level processing failure is `processing_status = failed`, overall run failed, but still has complete exact candidate outcomes;
- earlier transport/parser/normalization fatal/no-change paths keep processing `not_run`/zero;
- returned Worker/service processing state exactly matches persisted Collection-run state.

J. WORKER / SECURITY / PRESERVED UPSTREAM BEHAVIOR — LEVELS 1/3/5
Prove:
- Worker remains sole collection owner;
- Web/API does not fetch Sources inline;
- endpoint lock/eligibility/network safety/redirect safety remain in order;
- Phase 6 normalization/link policy regressions remain green;
- Worker output remains bounded and does not leak Raw bodies, summaries/full content, DB URLs/credentials, SQL, stack traces, or unbounded remote errors;
- one endpoint failure does not block a later unrelated endpoint execution.

MIGRATION EVIDENCE — LEVEL 4
Confirm production migrations:
- apply from zero in order through all Phase 7 migrations;
- rerun without repeated effects;
- representative Phase 6 -> Phase 7 upgrades preserve historical configuration/runs and truthfully mark historical processing not_run;
- Article/observation schema constraints/indexes remain intact;
- no existing migration checksum was rewritten.

LONG IDENTITY / INDEX EVIDENCE — LEVEL 4
