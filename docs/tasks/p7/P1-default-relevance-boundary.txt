MODULE BOUNDARY
Create substantive Relevance ownership under the collection pipeline, recommended:
- `src/collection/relevance/evaluator.ts`

Small supporting type files under `src/collection/relevance/` are allowed only when they materially improve clarity. Do not create a plugin framework or speculative abstraction for future rule types.

Define a small immutable typed decision contract suitable for later P5 integration. The Phase 7 decision should make these facts explicit:
- the candidate is included;
- the decision came from the canonical default/empty-rule path;
- the accepted candidate remains available to the next stage without mutation.

Use stable machine-readable semantics. Recommended shape is a discriminated immutable decision with an `included: true` or equivalent canonical field plus a stable reason such as `default_include`. Exact property names are implementation-owned, but callers MUST NOT need to infer inclusion from an empty array, undefined value, or thrown exception.

REQUIRED BEHAVIOR
- Every valid Article candidate passed to the Phase 7 evaluator receives the same deterministic default `include` decision.
- The evaluator MUST NOT bypass itself merely because there are no configured rules.
- The evaluator MUST NOT inspect or branch on indie-author/publishing terminology, configured Source names, Publication slugs, hostnames, or other topic-specific values.
- The evaluator MUST NOT mutate the candidate or provenance.
- Returned decision/result structures should be immutable/frozen consistently with the existing collection-domain style.
- No network, database, filesystem, clock, randomness, process environment, or global mutable state is allowed.
- Do not implement `exclude`, `categorize`, priority, Source-scoped rule precedence, ranking/boosting, or persistence yet. Those semantics remain governed by the contracts for the later configurable Relevance phase.

EXPECTED ERROR BOUNDARY
This function is called with already-normalized internal `ArticleCandidate` values. Do not invent broad untrusted-input validation or alternate fallback behavior here. Programming misuse may fail predictably, but ordinary Phase 7 behavior has no data-dependent rejection path.
