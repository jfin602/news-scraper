GOAL
Apply Phase 16's canonical ordinary-feed eligibility rule to the existing public read model:

An Article is eligible only when it already passes Publication/Source/visibility gates AND it is either:
- ungrouped; or
- the Primary member of its Duplicate group.

Visible non-Primary members remain stored and administratively available but are suppressed from ordinary public rows.

CANONICAL QUERY PLACEMENT
Modify the existing canonical Article eligibility stream in `src/public-feed/repository.ts`; do not bolt suppression onto serialization after pagination and do not create a second duplicate-aware feed implementation.

The duplicate condition belongs inside the same `eligible_items` relation/selection that already applies Source trust/lifecycle and Article visibility before keyset continuation/limit/order.

Use the persisted P1 topology as authority. A `NOT EXISTS` or equivalent relational predicate that excludes an Article only when it is a membership whose group Primary is a different Article is preferable to materializing a duplicate-role column.

Required consequences:
- an Article with no membership remains eligible if all existing gates pass;
- the group's `primary_article_id` remains eligible if visible and otherwise allowed;
- every other member is excluded before filtering/pagination output is selected;
- corrupt/missing topology must not be papered over with heuristic fallback; P1/P4 database invariants own topology correctness.

VISIBILITY REMAINS ORTHOGONAL
Do not reinterpret hidden/archived state when reading groups.

Cases:
- visible Primary + visible non-Primary -> only Primary may appear;
- hidden Primary + visible non-Primary -> no row from that group; do NOT silently promote/resurrect the visible non-Primary;
- visible Primary + hidden non-Primary -> Primary may appear;
- hidden/archived ungrouped Article remains excluded by existing visibility rules.

P6 does not mutate Primary or visibility.

DISCOVERY / FILTER / SEARCH SEMANTICS
Source filter, Category filter, literal keyword search, and keyset pagination must operate over the duplicate-suppressed canonical eligible stream.

Specifically:
- filtering to the Source of a visible non-Primary must not resurrect it;
- Category membership on a non-Primary must not resurrect it;
- a keyword matching only a non-Primary must not resurrect it;
- combined `q + source + category` remains AND behavior over eligible rows;
- cursor continuation is computed only from rows that are eligible after duplicate suppression;
- suppression must not create duplicate/omitted rows across pages in a static result set;
- effective-feed-date -> `first_seen_at` -> Article-ID ordering remains unchanged;
- cursor encoding/version/query-binding remain unchanged unless source drift proves a concrete compatibility need.

Do not change Source/Category choice metadata merely to hide options that currently have no eligible row; those choices are separately governed public discovery metadata and are not duplicate roles.

PUBLIC DESTINATION / PRESENTATION
The selected Primary row still uses its own stored `original_url`, display title, Source name, effective date, and current Category membership exactly as existing feed behavior does.

Do not:
- synthesize an original-publisher destination from another group member;
- display an “also reported by” aggregate;
- combine titles/summaries/categories across members;
- expose group IDs/internal membership in the basic public feed;
- alter Publication presentation/timezone behavior.
