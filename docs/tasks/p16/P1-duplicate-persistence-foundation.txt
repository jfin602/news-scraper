DUPLICATE REVIEW PERSISTENCE
Persist one logical review relationship per canonical unordered pair of distinct Articles.

The representation must support:
- stable candidate UUID;
- canonical `article_low_id` / `article_high_id` Article FKs with a database check enforcing strict canonical order and preventing self-pairs;
- database uniqueness for the logical unordered pair so `(A,B)` and `(B,A)` cannot coexist;
- state vocabulary `pending`, `dismissed`, `merged`, `superseded`;
- origin vocabulary `automatic`, `manual` so Phase 17 can later use the same record without Phase 16 adding UI;
- one bounded deterministic confidence value using a documented integer scale such as 0..100;
- a stable evidence fingerprint capable of distinguishing materially changed deterministic evidence;
- created/updated timestamps;
- nullable manual-decision timestamp/reason fields only as persistence capacity required by the governing contract; do not build manual commands/UI in P1.

Persist ordered deterministic signals/reasons for each candidate in a normalized child relation rather than opaque unbounded JSON. Each signal row should identify a bounded machine reason code and whether the signal is `strong` or `weak`; preserve deterministic ordering. Use real FKs and bounded shape constraints. Do not store Article bodies or speculative semantic vectors.

Article deletion/cascade behavior must never make duplicate persistence a path that deletes Article instances or Article observations. Use restrictive Article relationships appropriate to the current no-Article-deletion Phase 16 model.

DUPLICATE GROUP TOPOLOGY
Persist installation-wide Duplicate groups and memberships with no Publication tenant key.

Required database invariants:
- an Article belongs to at most one Duplicate group;
- every group has one non-null `primary_article_id`;
- the Primary Article must be a membership of that same group;
- the schema must not encode duplicate role into `articles.visibility_state` or otherwise conflate visibility and grouping;
- group membership never deletes or rewrites Article/observation provenance.

Prefer a compact model where `duplicate_groups` owns `primary_article_id` and `duplicate_group_memberships` owns `(group_id, article_id)`, with one-group-per-Article uniqueness. Use a deferred/composite FK or equivalently strong PostgreSQL design so a group cannot commit with a Primary that is not its member while still permitting transactional group creation. Do not add a redundant membership `role` column if the group row is already the single Primary authority.

P1 adds no operator merge/split/delete behavior. Group-row/member cascade behavior may clean up membership rows when a group itself is deliberately removed later, but must never cascade into Articles or observations.

ARTICLE LOOKUP SUPPORT
Later detection must compare separately persisted Articles across Sources without a full-table scan for the two Phase 16 signals currently governed.

Add only the lookup support actually needed for:
- cross-Source exact `canonical_identity_url` comparison, while always checking the full stored string after any digest lookup;
- exact `normalized_title` equality as weak review-only evidence, while checking the full stored title after any digest lookup.

Reuse existing digest conventions where safe. A global canonical-identity digest lookup index and a bounded expression/digest lookup for normalized title are acceptable. Do not add fuzzy/vector/full-text infrastructure or change Source-scoped Article identity indexes.
