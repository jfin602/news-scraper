GOAL
Make approved persisted `html_listing` endpoints collect through the existing canonical Worker pipeline, using endpoint-type-aware HTTP content policy and parser dispatch while keeping all downstream behavior shared.

P3 is complete only when HTML collection uses the same eligibility, endpoint lock, SSRF/redirect protection, scheduling/jobs, conditional-fetch state, normalization, Article-link validation, Relevance/Categories, Source-scoped Article identity/persistence/observations, duplicate processing, run accounting, retry, health, and failure-isolation boundaries already used by RSS/Atom.

There must not be an HTML-specific Article repository, Relevance path, duplicate path, public-feed path, scheduler, or second collector.

CANONICAL EXECUTION ORDER
Preserve this logical order:

configured endpoint
→ collection eligibility
→ shared endpoint/capacity locks
→ Collection run start
→ approved destination + DNS/address/port safety
→ bounded HTTP fetch with redirect revalidation
→ endpoint-type parser dispatch
→ RSS/Atom Source admission filter only for `rss_atom`
→ shared Article-candidate normalization
→ shared Article-link policy
→ shared Relevance/Categories
→ shared Source-scoped Article identity/persistence/observation
→ shared duplicate processing
→ Collection-run finalization
→ existing endpoint runtime/retry/health application.

Do not move Source admission after normalization and do not route HTML through it.

ENDPOINT-TYPE-AWARE HTTP POLICY
Refactor HTTP transport/fetch request options only as far as needed to carry a small explicit content/media policy derived from endpoint type.

Required behavior:
- `rss_atom` keeps the currently accepted feed/XML terminal media types and current RSS/Atom `Accept` behavior;
- `html_listing` advertises ordinary static HTML and accepts at least `text/html` terminal content;
- standards-compatible XHTML may be accepted only if P1's actual parser deliberately supports it and tests prove it;
- adding HTML must not globally make RSS endpoints accept `text/html` or arbitrary `*/*` content;
- 304/redirect/non-2xx behavior keeps existing semantics;
- compression, wire/decompressed size limits, connection/total timeouts, response-header bounds, retry classification, selected validated address binding, TLS/Host behavior, and redirect-hop safety remain unchanged;
- media policy is chosen from persisted endpoint type, not from Content-Type sniffing that silently changes adapters.

Prefer passing a small normalized response/content policy through `HttpFetcher` → transport rather than coupling low-level transport to the full endpoint aggregate.

Do not fetch anything except the configured endpoint plus already-governed redirect hops.

PARSER DISPATCH
Replace direct RSS parser construction/use with one truthful endpoint-type dispatch boundary.

Required behavior:
- `rss_atom` invokes the existing RSS/Atom parser;
- `html_listing` invokes P1's static HTML parser using the exact persisted normalized profile snapshot from P2;
- unknown/unsupported endpoint types fail closed and never guess a parser;
- parser adapter kind/version/profile revision/item-failure diagnostics flow to the P2 Collection-run finalization contract;
- parser failure remains an isolated terminal failure for that endpoint/run and does not interrupt unrelated Source jobs.

Keep dispatch small and explicit. Do not create a speculative general plugin framework or dynamic module loader for two known endpoint types.

RSS/ATOM ADMISSION FILTER SEPARATION
Current Source admission phrases are specifically RSS/Atom behavior.

Refactor collection flow so:
- after successful RSS/Atom parse, existing admission phrases run exactly as before;
- after successful HTML parse, Raw items bypass Source RSS/Atom admission evaluation and proceed directly to shared normalization;
- `source_item_filtered_count` remains `0` for HTML runs;
- HTML profile matching/extraction failures are parser diagnostics, not Source admission mismatches and not Relevance exclusions;
- absent/matching RSS/Atom phrase behavior and existing accounting remain unchanged.

Add tests that use a Source with configured RSS/Atom admission phrases and an HTML endpoint to prove HTML items are not filtered by those phrases.

TERMINAL URL / NORMALIZATION
Preserve `HttpFetcher`'s final successfully fetched URL after approved redirects as the base URL supplied to Article-candidate normalization.

HTML relative Article links must therefore resolve through the same canonical normalizer against the terminal endpoint URL. Do not resolve relative links inside the HTML parser and do not use the originally configured pre-redirect URL when the actual terminal URL differs.

COLLECTION-RUN / RUNTIME BEHAVIOR
Integrate P2 diagnostics into existing run start/finalization without inventing parallel HTML statuses.

For HTML content runs record as applicable:
- parser adapter kind/version;
- exact profile revision from the endpoint snapshot;
- item/extraction failure summary;
- bounded terminal parser failure code/detail.

Preserve:
- `raw_item_count` as successfully emitted Raw items entering the downstream stage, with parser-specific malformed matched-row counts represented separately rather than corrupting normalization arithmetic;
- `source_item_filtered_count = 0` for HTML;
- existing normalization/Article-link/processing/duplicate effect arithmetic over emitted Raw items/candidates;
- conditional ETag/Last-Modified state and 304 no-change behavior;
- endpoint runtime state application only after canonical terminal run finalization;
- durable job attachment/recovery semantics;
- retry classification and scheduler/backoff behavior.

If current run accounting defines `raw_item_count` differently in a way that conflicts with P2/P1 diagnostic representation, stop and report the exact contract conflict rather than silently redefining historical counters.

NO CRAWLING / SUBRESOURCE GUARANTEE
The implemented HTML collector must issue no network request for:
- Article URLs extracted from the page;
- pagination/next-page links;
- images;
- stylesheets;
- scripts;
- frames/embeds;
- canonical/alternate metadata links;
- discovered Source/feed URLs.

It also must not invoke Playwright/Puppeteer/headless browser fallback.

The static parser receives only bytes already fetched by the canonical one-endpoint HTTP path.
