GOAL
Expose the installation's complete singleton Publication configuration through the existing protected admin API.

P2 owns the Publication read/update service and HTTP routes. It does not build the browser editor, Category/Relevance CRUD, or a second Publication model.

ADMIN SERVICE BOUNDARY
Create a focused Publication administration service under `src/admin/` or the current canonical admin ownership path.

The service should expose a bounded operator read model containing:
- `name`;
- `activeForCollection`;
- `publicStatus`;
- nullable/optional `description`;
- nullable/optional `logoPath`;
- nullable/optional `accentColor`;
- nullable/optional `presentationTimezone`.

Use the existing Publication normalization functions from P1 rather than duplicating field validation in the admin layer.

Provide one complete replacement-style update command for the mutable singleton Publication configuration. The request body should use an exact known-key shape and reject unknown fields rather than silently accepting typo/future properties.

The command must update the existing singleton row atomically and return the canonical persisted read model. It MUST NOT create a Publication UUID, slug, selector, route parameter, tenant scope, or second settings row.

If singleton settings are absent, return one stable bounded application error rather than implicitly bootstrapping a new Publication through the admin route.

STATE SEMANTICS
`activeForCollection` and `publicStatus` are distinct controls:
- `activeForCollection` governs whether otherwise eligible Sources/endpoints may collect/schedule;
- `publicStatus` governs whether the canonical public feed/page is exposed;
- changing one MUST NOT silently change the other.

A Publication may be private while collection remains active, or public while collection is disabled. Preserve this distinction in validation/tests.

Presentation fields remain inert bounded configuration. `presentationTimezone` retains P1's presentation-only semantics and cannot modify stored timestamps/order/cursors.

RECOMMENDED HTTP API
Integrate through the existing `/api/admin` router and request-integrity middleware. Use this compact canonical surface unless established route conventions strongly justify an equivalent name:

`GET /api/admin/publication`
`PUT /api/admin/publication/configuration`

The GET route is read-only and needs no mutation header. The PUT route inherits the canonical JSON/content-length/custom-header controls from `admin-router.ts`.

Do not create separate routes for every individual Publication field unless current implementation architecture demonstrates a concrete need. One validated replacement command is simpler and keeps Publication state coherent.

ERROR SHAPING
Return bounded stable JSON errors for:
- invalid request/configuration;
- missing singleton Publication settings;
- bounded dependency/internal failure through the existing generic admin error boundary.

Do not leak SQL, stack traces, environment values, raw database rows, internal headers/tokens, or implementation-only details.

WEB COMPOSITION
Register Publication routes beside the existing Source/endpoint admin registrars without weakening:
- admin-disabled fail-closed behavior;
- no-store/security/CSP headers;
- canonical mutation request-integrity checks;
- public route isolation.

Do not treat caller-supplied Cloudflare headers as application authentication and do not add native administrator accounts/sessions/roles.

TESTING
Add focused unit/integration/database coverage for:
- read existing singleton Publication configuration including timezone;
- complete update/round-trip of all governed fields;
- exact-key unknown-field rejection;
- existing name/description/logo/accent/timezone validation errors map to bounded admin errors;
- missing singleton configuration returns the intended bounded result and does not create a row;
- changing `publicStatus` immediately affects the existing canonical public-feed availability path without changing collection state;
- changing `activeForCollection` is observed by the existing collection-eligibility path without changing public status;
- private + active and public + inactive combinations remain valid/distinct;
- timezone edit does not rewrite Article timestamps/order/cursors;
- missing/wrong mutation header, non-JSON body, malformed JSON, and oversized JSON cannot mutate Publication state;
- admin-disabled routes remain unavailable;
- public `/` and `/api/feed` behavior remains otherwise unchanged;
- no Publication selector/ID/slug is introduced in route/service/repository signatures.

Use real disposable PostgreSQL for persisted update/state claims. Reuse existing admin HTTP harnesses and public/eligibility regression tests where practical instead of creating duplicate infrastructure.

PRESERVED BEHAVIOR
Preserve ordinary bootstrap no-overwrite behavior, singleton Publication persistence, Worker-owned collection, Source/endpoint approval/network safety, public-feed eligibility/order/discovery, Phase 13 presentation, Phase 14 admin perimeter/request-integrity, and topic independence.
