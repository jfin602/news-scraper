MODEL / REASONING / USAGE
- Recommended configuration: `Sol Light`.
- Model-family basis: closeout is an independent final review boundary, so Sol's stronger base code-reading and review capability is preferred even though the Phase 15 evidence matrix is explicit and bounded.
- Reasoning basis: Light reasoning is sufficient for the governed three-pass closeout workflow: execute the explicit contract/evidence matrix, independently derive and challenge realistic error/edge cases from the final implementation, then perform a separate code-quality/structural review; deeper reasoning is reserved for an observed failure that cannot be confidently classified as a bounded closeout defect.
- Complexity / quality floor: `High`.
- Estimated usage: `High`.
- Lower-cost alternative considered: `Luna High`; rejected for closeout because the workflow intentionally uses Sol Light as the independent-review baseline to improve the chance of catching implementation, failure-mode, and code-quality gaps left by cheaper implementation prompts without paying for high reasoning by default.
- Escalation trigger: any closeout pass exposes material architectural ambiguity, difficult cross-subsystem root-cause analysis, concurrency/transaction ownership uncertainty, security-boundary uncertainty, or another defect that cannot be confidently classified and repaired within the bounded Phase 15 closeout contract.
- Escalation target: `Terra Ultra` when the dominant need is deeper reasoning over explicit state/transaction interactions; use a higher-effort Sol configuration instead if the blocker requires stronger independent cross-system inference or ambiguous contract reconciliation. A meaningful behavior-preserving structural refactor uses the separate `Terra High` refactor-handoff procedure below instead of this hard-reasoning escalation path.
- Estimate confidence: `High`.
- Efficiency rationale: Sol Light buys stronger independent review capability at low reasoning cost; validation volume alone does not justify a higher-effort model, while the explicit adversarial error pass, structural pass, escalation rule, and refactor handoff prevent the closeout from merely certifying happy-path work produced by weaker implementation models.
