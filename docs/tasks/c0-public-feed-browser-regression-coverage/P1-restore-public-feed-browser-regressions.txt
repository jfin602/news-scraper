TASK: Correction 0 / P1 — Restore public-feed browser regressions

CORRECTION SCOPE
This correction repairs the evidence regression discovered by the RED post-1.0 Phase 0 closeout. The current Phase 0 implementation at commit `905da50274db8584ac938dbe456121b2ea4b8f05` introduced the intended server-rendered root/progressive-enhancement architecture, but `test/browser/public-feed-page.test.ts` was reduced from the prior broad browser regression matrix to six scenarios. The closeout therefore could not prove preserved browser behavior, stale-request safety, continuation guards, history behavior, presentation parity, or the complete JavaScript-disabled contract.

This prompt restores/adapts the missing governed browser proof against the CURRENT SSR lifecycle. It is not permission to revert Phase 0, resurrect the obsolete client-owned initial page fetch, or inflate the suite by mechanically copying historical tests.

- Recommended configuration: `Terra Medium`.
- Model rationale: the behavior is explicit and the production architecture is already settled, but the work still requires meaningful reasoning across SSR bootstrap state, enhanced first-page generation/AbortController ownership, history, continuation generations, cursor guards, asynchronous browser races, and test-fixture ownership. Terra Medium is the minimum reliable balanced tier for that stateful adaptation.
- Lower-cost alternative considered: `Luna High`; rejected because the difficult part is preserving asynchronous browser-state invariants and translating old lifecycle assumptions, not writing Playwright syntax.
- Escalation trigger: an adapted regression exposes a production defect that requires non-local restructuring of SSR bootstrap ownership, first-page request generations, history state, or continuation architecture rather than one bounded unambiguous repair.
- Escalation target: `Terra High`.
- Expected usage: Very High because the browser matrix is large; usage volume alone is not an escalation reason.

ALL OTHER STILL-GOVERNED BEHAVIOR
Restore or coherently adapt observable browser proof for the substantive prior behaviors that Phase 0 did not intentionally remove. Consolidation is allowed only when the resulting test still diagnoses the protected behavior clearly.

At minimum cover these groups:

A. SSR STARTUP / PRESENTATION
- configured Publication name/description/logo/accent/title is present and stable from SSR startup;
- a broken SSR logo degrades safely even if its error event occurs before deferred client startup; later API presentation changes also retain deterministic broken-logo behavior;
- absent optional presentation removes/hides the relevant elements cleanly;
- initial correct SSR page generates zero `/api/feed` requests;
- exact SSR Article nodes/row identity remain present through client startup rather than being replaced merely for hydration;
- configured presentation timezone produces the same intended calendar date independently of viewer timezone; null timezone preserves UTC fallback.

B. CONTENT / NAVIGATION / RESPONSIVE BEHAVIOR
- hostile markup-looking Publication, Source, Category, headline, and Source-name content remains inert in the browser;
- exact stored external publisher `original_url` remains the headline destination;
- representative desktop/mobile widths do not create horizontal document overflow;
- feed row/column presentation remains coherent at desktop and mobile widths;
- relevant native controls/headline/load-more targets remain usable/focus-visible where this behavior is not already equivalently owned by `public-feed-theme.test.ts`;
- do not duplicate the full theme contrast/persistence/keyboard contract merely to increase coverage count.

C. DISCOVERY / ROOT / HISTORY
- direct q/source/category URL criteria start from corresponding SSR state with zero initial API requests;
- refresh reconstructs that root state without a startup API fetch;
- enhanced combined q/source/category Search emits deterministic root URL criteria and corresponding `/api/feed` criteria;
- Source-only and Category-only enhanced discovery work independently;
- Reset from a resolved filtered page returns to `/` and uses the existing enhanced first-page API path when JavaScript is enabled;
- Back/Forward restores criteria and first-page rows without adding cursor depth to the root URL;
- after load-more depth, Back/Forward restores the first URL page for each history entry rather than reconstructing old continuation depth;
- malformed direct root discovery is handled by the SSR root contract rather than being repaired into an API call;
- literal and percent-encoded root `cursor` parameter names are rejected by root Phase 0 semantics with no client feed reconstruction.

D. ENHANCED FIRST-PAGE OWNERSHIP / RACES
Adapt/reintroduce deterministic controlled-fetch/deferred-promise tests so later enhanced first-page requests prove:
- resolved branding remains visible/coherent while Search, Reset, or popstate replacement is pending, while old Article rows are cleared according to existing governed transition behavior;
- an owned enhanced 404/unavailable response clears stale prior Publication presentation as currently governed;
- malformed successful API payloads fail to a generic bounded client error state;
- malformed Publication presentation in a successful enhanced API response fails safely;
- stale success, stale 404, and stale network/error responses cannot overwrite a newer owned first-page result/branding;
- a slow enhanced Apply cannot overwrite a newer Reset result;
- slow enhanced Apply/history requests cannot overwrite a newer popstate/Forward result.

Controlled-fetch indexing MUST reflect Phase 0 ownership:
- root SSR startup is a real server navigation, not controlled fetch request zero;
- controlled request index 0 is the FIRST enhanced `/api/feed` request generated after startup.
Do not fake an initial `/api/feed` call merely to preserve historical helper indices.

E. CONTINUATION / CURSOR SAFETY
Starting from an SSR-supplied `nextCursor`, prove:
- Load More uses the current opaque cursor plus active criteria and never adds cursor depth to the root browser URL;
- appended Articles remain in server order, use exact publisher links, preserve presentation timezone formatting, and keep hostile appended text inert;
- continuation Publication/discovery metadata does not unexpectedly replace first-page-owned Publication/controls if the existing contract does not permit that;
- no Load More control exists for a final first page;
- while a continuation is pending, keyboard/click reactivation cannot issue duplicate continuation requests;
- a successful continuation can replace the cursor and the next Load More uses the replacement cursor;
- resolving the same response path again cannot append the same page twice;
- duplicate Article IDs against already-rendered items cause a local continuation failure, do not mutate existing rows/cursor, and allow safe retry;
- repeated continuation cursor is rejected locally;
- an empty continuation page carrying a non-null cursor is rejected locally;
- network abort/failure, malformed JSON, 400, 404, 503, mismatched criteria, and malformed successful payloads remain local continuation failures that preserve existing rows and allow retry where governed;
- a later valid retry can append safely and clear the local failure state;
- criteria change after loaded depth discards old continuation depth and makes a first-page API request without a cursor;
- Source, Category, keyword, Reset, and history transitions all invalidate old continuation state.

F. STALE CONTINUATION RACES
Restore deterministic browser proof that:
- a slow continuation invalidated by Apply cannot append or display a stale failure after the newer first page owns the UI;
- a slow continuation invalidated by Reset cannot append after the fresh unfiltered first page;
- a slow continuation invalidated through Back/Forward cannot append after restored state;
- an abort-insensitive stale continuation SUCCESS after Apply is ignored;
- an abort-insensitive stale continuation FAILURE after Reset/history is ignored;
- stale continuation outcomes cannot reintroduce pagination errors or stale controls into the newer owned state.
