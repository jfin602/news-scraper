CURRENT PROBLEM
The current wrapper always launches Node with `--test-concurrency=1`, so every discovered test file is serialized. Package scripts route ordinary, browser, database, and live-source suites through the same wrapper. This creates unnecessary wall-clock cost for independently isolated files and encourages repeated broad reruns during development.

The current runner also sorts selected files, and existing runner tests must preserve deterministic discovery/selection without treating completion/stdout order between independent processes as a correctness invariant.

GOAL
Make file-level test concurrency an explicit, bounded runner capability; assign conservative suite-specific values through package scripts; add a focused real-database command for iterative development; and preserve every existing fail-closed selection/global-setup/failure semantic.

RUNNER CONCURRENCY CONTRACT
Extend `scripts/run-tests.mjs` with one explicit option:

`--test-concurrency=<positive integer>`

Required behavior:
- direct/default wrapper execution remains concurrency `1` unless the caller explicitly supplies another value;
- accept exactly one concurrency option;
- reject empty, zero, negative, fractional, non-numeric, duplicate, or otherwise malformed values with a clear nonzero failure before Node test execution;
- remove runner-owned options from the glob-pattern list;
- continue accepting at most one non-empty `--test-global-setup=...` option;
- preserve deterministic glob expansion, path normalization, de-duplication, and lexical sorting before execution;
- continue failing when no patterns are supplied or no files match;
- continue deleting inherited `NODE_TEST_CONTEXT` from the child environment;
- pass the selected integer to Node as exactly one `--test-concurrency=<n>` argument;
- preserve child exit status/error propagation;
- do not add automatic retries or a second test-runner framework.

Do not infer concurrency from CPU count, environment heuristics, or file count. The package scripts own explicit bounded values so validation behavior is stable and auditable.

PACKAGE SCRIPT POLICY
Update current scripts to choose these initial conservative file-concurrency values:
- `test` -> 4
- `test:unit` -> 4
- `test:integration` -> 4
- `test:collection` -> 4
- `test:browser` -> 2
- `test:db` -> 1 in this prompt
- `test:live-sources` -> 1

These are implementation tuning values, not new product contracts. Preserve current test globs and `.env`/global-setup behavior.

Do not change `npm run check` containment: it should continue to execute format check, lint, typecheck, and the ordinary `npm test` regression matrix once.

FOCUSED DATABASE COMMAND
Add a substantive package command:

`npm run test:db:focused -- <file-or-glob> [additional file-or-glob ...]`

Required behavior:
- the script itself MUST NOT provide a default database glob;
- invoking it without a selected file/glob must fail through the wrapper rather than silently launching the entire DB suite;
- preserve `.env` loading;
- preserve `test/support/database/database-test-global-setup.ts` prerequisite/preflight behavior;
- use real PostgreSQL exactly like the full database suite;
- retain selected-test zero-match failure;
- keep focused DB file concurrency at `1` in P1;
- do not introduce mocks or a different database configuration path.

RUNNER REGRESSION TESTS
Update/add focused runner tests proving at minimum:
- default invocation uses concurrency 1;
- explicit valid concurrency reaches the Node child invocation exactly;
- malformed/duplicate concurrency options fail closed;
- deterministic file discovery/selection and duplicate-glob de-duplication remain;
- zero patterns and zero matches remain failures;
- global setup remains accepted exactly once and still reaches Node;
- child nonzero status/error still fails the wrapper;
- a multi-file concurrent fixture proves independent files can overlap without depending on exact completion order;
- existing tests no longer require `fixture-a` output to complete before `fixture-z` output merely because discovery is sorted.

Prefer a deterministic barrier/coordination fixture or another robust concurrency proof over a brittle assertion that only compares elapsed milliseconds.
