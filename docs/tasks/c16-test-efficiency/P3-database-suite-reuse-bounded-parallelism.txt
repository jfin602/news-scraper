- Escalation target: stop and report planning drift rather than silently broadening the architecture; do not switch families merely because the conversion is large.

CONVERSION RULES
For each reusable file:
- create one file-scope migrated/bare helper instance, not one process-global DB;
- each test case receives a clean application-data state through the P2 reset lifecycle;
- preserve existing fixture creation and behavioral assertions as closely as possible;
- close every case-owned `Database`, `Client`, Pool, spawned role, or other database consumer before the scope callback returns;
- keep intentional same-database actors inside a case when the behavior under test is locking/racing/concurrency;
- do not alter product transaction boundaries to make test cleanup easier;
- do not replace SQL constraint/race assertions with unit mocks;
- do not merge logically independent test cases solely to save setup time;
- do not share one mutable DB between concurrently executing test files.

BOUNDED DATABASE FILE PARALLELISM
Only after converted files pass in focused batches:
- change full `npm run test:db` file concurrency from 1 to exactly 2;
- keep `npm run test:db:focused` at concurrency 1 for predictable diagnosis and low connection pressure;
- preserve the DB global setup/preflight and `.env` handling;
- ensure each parallel file owns a distinct physical database when it uses a reusable scope;
- preserve fresh standalone files' own distinct disposable databases;
- do not derive DB concurrency from CPU count;
- do not raise above 2 in this correction without stopping for explicit replanning and measured evidence.

The conservative limit is intentional because individual test files may create several `Database` pools/clients and production `Database` pools have finite connection capacity. The primary speedup should come from eliminating repeated create+migrate+drop work, not aggressive oversubscription.
