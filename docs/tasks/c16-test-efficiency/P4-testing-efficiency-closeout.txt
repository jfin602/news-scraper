B. POSTGRESQL HARNESS EVIDENCE

- migrated scope runs the production migration path once per physical scope, not once per test case;
- application-data reset excludes `news_scraper_schema_migrations` and preserves schema/indexes/constraints;

- one scope cannot be used concurrently;
- final cleanup force-drops and verifies database absence;
- callback/reset/cleanup failures cannot become silent green results;
- no outer transaction is being used as a fake universal reset mechanism.

PASS 2 — ERROR / EDGE-CASE ADVERSARIAL REVIEW

At minimum investigate:
- one file leaving rows that affect the next case;
- one file leaving an open transaction/client that blocks reset;
- migration ledger accidentally truncated or mutated;
- reset table discovery missing a current application table;
- table identifier quoting/order problems;
- sequences/identity state leaking between tests;
- a failed callback leaving state that the next case observes;
- two callbacks sharing one scope concurrently;
- two parallel files accidentally sharing one database name/state;
- full DB concurrency oversubscribing PostgreSQL enough to cause intermittent failures;
- database name collisions or cleanup races;
- advisory-lock tests interacting across independent databases unexpectedly;
- process-based readiness/Worker tests surviving beyond callback cleanup;
- hybrid files accidentally migrating a fixture intended to remain uninitialized;
- full migration/lifecycle tests accidentally routed through reusable migrated state;

- runner option parsing treating an option as a glob or vice versa;
- a concurrent child failure being hidden by another passing child;
- browser concurrency causing shared port/global-state interference;
- output scheduling assumptions remaining in tests;
- live-source tests accidentally becoming concurrent;
- final aggregate validation scripts no longer containing the evidence the prompt assumes.
