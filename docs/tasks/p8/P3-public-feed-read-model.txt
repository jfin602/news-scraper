MODULE OWNERSHIP
Create the first substantive public-feed module, expected as:
- new `src/public-feed/repository.ts`

Keep the boundary read-only and database-backed.

A suitable public API is conceptually:
- `readPublicFeed(executor, publicationSlug): Promise<PublicFeed | undefined>`

Exact naming may follow repository conventions.

`undefined` must represent both:
- Publication slug does not exist;
- Publication exists but `public_status != public`.

That intentional collapse prevents later HTTP composition from distinguishing private from missing Publications on the public surface.

INTERNAL READ MODEL
Establish one small typed model equivalent to:

PublicFeed:
- publication:
  - `id`
  - `slug`
  - `name`
- items:
  - `articleId`
  - `effectiveFeedDate` as `Date`
  - `feedDateSource` exactly `published_at` or `first_seen_at`
  - `headline` from Article `display_title`
  - `sourceName` from Source `display_name`
  - `originalUrl` from Article `original_url`

Do not expose storage-only fields merely because they are available.

PUBLIC ELIGIBILITY — CONTRACT CRITICAL
An ordinary Phase 8 row is eligible only when ALL are true:
- owning Publication `public_status = 'public'`;
- owning Source `approval_state = 'approved'`;
- owning Source `lifecycle_state = 'active'`;
- Article `visibility_state = 'visible'`.

Before true duplicate grouping exists, Articles are logically `ungrouped`; do not add or query speculative duplicate group/role persistence.

DO NOT USE THESE AS PUBLIC-ROW SUPPRESSION GATES
The reader MUST NOT suppress an otherwise eligible retained Article merely because of:
- Publication `active_for_collection = false`;
- Source `operational_state = paused|disabled`;
- Source endpoint approval/lifecycle/operational state;
- endpoint health;
- current/latest Collection run success/failure;
- scheduler/job state.

Prefer a query that touches only `publications`, `sources`, and `articles` for ordinary feed eligibility. Do not join endpoints/runs just because provenance exists.

PUBLICATION / SOURCE / ARTICLE OWNERSHIP
Use the persisted ownership relationships correctly so rows cannot bleed across Publications/Sources.

The requested slug must resolve exactly one public Publication, and every returned Article/Source must belong to that Publication through the existing foreign-key relationships.

CANONICAL EFFECTIVE FEED DATE
For each eligible Article:
1. if `published_at_status = 'parsed'`, effective date is stored `published_at` and `feedDateSource = 'published_at'`;
2. otherwise effective date is `first_seen_at` and `feedDateSource = 'first_seen_at'`.

Do not fabricate publication dates. The existing Article schema already enforces parsed/missing/invalid timestamp consistency; use that invariant rather than adding a second normalization system.

DETERMINISTIC ORDER
Order items exactly:
1. effective feed date DESC;
2. `first_seen_at` DESC;
3. Article stable UUID/id ASC as final deterministic tie-breaker.

Do not sort by Source name, title, `updated_at`, `last_seen_at`, endpoint state, or collection-run time.

BOUNDED PHASE 8 WINDOW
Return at most 100 eligible items for one Publication.

The limit is server-defined and fixed in Phase 8:
- no caller-supplied limit;
- no offset;
- no cursor;
- no load-more token.

Phase 12 owns discovery/pagination behavior.

QUERY DESIGN
Use one coherent parameterized database query (or a minimal fixed number only if clearly safer) that:
- resolves public Publication identity;
- returns Publication identity even when there are zero eligible items;
- applies all eligibility predicates at the DB read boundary;
- calculates effective date/source deterministically;
- orders before limiting;
- avoids N+1 Source/Article lookups.

A CTE/lateral/subquery structure is acceptable if it preserves the contract and remains maintainable. Do not use dynamic SQL.

SAFE MAPPING / FAILURE BOUNDARY
Map database rows defensively into the typed public-feed model.

Invalid/unexpected database row shapes should fail through one bounded public-feed repository error/type rather than returning partially trusted data. Do not include SQL, credentials, raw rows, stack traces, or database detail in the error message.

Do not re-use `ArticlePersistenceError` for this read-side concern merely because it exists.

OUTPUT MINIMIZATION
The production read model MUST NOT include:
- Article `normalized_title`;
- `canonical_identity_url` or identity digests;
- external ID;
- author/summary/image/language unless separately promoted later;
- Article observations or Collection-run provenance IDs;
- Source site URL/config key/state fields;
- endpoint data;
- Relevance internals;
- raw content.

The public destination is always stored Article `original_url`, even when it differs from `canonical_identity_url`.

FOCUSED PUBLIC-FEED DATABASE MATRIX — LEVEL 4
Use real disposable PostgreSQL and prove at minimum:

A. Publication exposure/isolation
- public Publication is readable;
- private Publication returns `undefined`;
- missing slug returns `undefined`;
- private and missing are indistinguishable at the repository API boundary;
- public Publication with `active_for_collection = false` remains readable;
- Articles from another Publication never appear.

B. Source trust/lifecycle versus operations
- approved + active Source Article is included;
- unapproved Source Article is excluded;
- archived Source Article is excluded;
- approved active Source with operational state `paused` remains readable;
- approved active Source with operational state `disabled` remains readable.

C. Endpoint/run state separation
Where fixture setup includes endpoints/runs, prove that changing endpoint operational/lifecycle conditions or preserving a failed/old Collection run does not hide an otherwise eligible retained Article. Do not alter the Source approval/lifecycle gate to accomplish this.

D. Article visibility
- `visible` included;
- `hidden` excluded;
- `archived` excluded.

E. Feed-date semantics
- parsed `published_at` wins over `first_seen_at`;
- missing publication date falls back to `first_seen_at`;
- invalid publication date falls back to `first_seen_at`;
- `feedDateSource` reports the actual branch.

F. Deterministic ordering
- later effective date before earlier;
- same effective date sorts by `first_seen_at` descending;
- same effective date + same first-seen sorts by Article id ASC;
- repeated reads return the same order.

G. Bounds/empty state
- a public Publication with no eligible rows returns Publication identity + empty items;
- 101+ eligible rows returns exactly the newest 100 according to canonical ordering.

H. Safe shaping/destination
- Source display name maps correctly;
- headline maps from `display_title`;
- `originalUrl` is exactly stored `original_url`;
- make `canonical_identity_url` deliberately different in a fixture and prove it is not returned/substituted;
- returned object exposes no extra internal fields.
