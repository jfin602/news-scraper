TASK: Phase 7 / P2 — Managed News Scraper release qualification

- Recommended configuration: `Terra High`.
- Task-shape classification: `Cross-cutting`.
- Specification clarity: `Explicit`.
- State coupling: `High`.
- Integrity risk: `High`.
- Concurrency: `Cross-process`.
- Security: `Sensitive`.
- Novel inference: `Moderate`.
- Model-family basis: P2 qualifies the already-implemented managed Web/Worker/PostgreSQL/distribution chain rather than designing it, but the task spans supported production migration/recovery, real approved Sources, protected Profile/credential state, machine authentication/rate limits, snapshot pagination, trusted-proxy deployment behavior, and operational telemetry. Terra is the minimum family with enough integrated state/security judgment.
- Reasoning basis: High reasoning is warranted because evidence must distinguish real managed observations from deterministic tests, preserve the accepted production database, coordinate disposable validation credentials/Profile mutations safely, and diagnose any release blocker without widening Phase 7 into architecture work.
- Complexity / quality floor: `High`.
- Estimated usage: `High`.
- Lower-cost alternative considered: `Terra Medium`; rejected because the combined production-upgrade/recovery/security/live-deployment boundary has multiple failure and rollback states whose interaction matters to the 2.0 gate.
- Escalation trigger: an observed managed failure exposes uncertain transaction ownership, migration/data-loss risk, a difficult credential/rate/security boundary, a nontrivial concurrency/race defect, or a release blocker whose correct repair is not explicit from current contracts.
- Escalation target: `Terra Ultra` for explicit deep transaction/recovery/state-machine reasoning; higher-effort Sol only for ambiguous cross-system contract/architecture reconciliation; return `Planning needed` for material new product capability.
- Estimate confidence: `High`.
- Efficiency rationale: prove the upstream managed half once against the real candidate, use existing specialized suites instead of rebuilding them, and leave customer-host LKG/SSR failure proof to P3.

## Real machine-authenticated v1 API observations

Use the dedicated credentials and Profile against the real managed HTTPS endpoint.

Observe at minimum:

### Normal multi-page traversal

- first request returns `200` with expected v1 envelope shape and a non-null cursor;
- continuation returns another `200`;
- Profile key remains the requested immutable key;
- `snapshotRevision` remains identical across the unchanged traversal;
- page ordering is stable and there is no duplicate/missing boundary item caused by pagination;
- exact stored `originalUrl` values are preserved;
- a conditional initial request using the observed ETag/revision behavior produces the governed unchanged response when applicable;
- no browser CORS assumption is needed.

Do not build an adapter-side validator that reimplements Profile filtering or cursor decoding. Observe the wire contract and let the real API/PHP client remain the semantic owners.

### Invalid and revoked authentication

- a deliberately invalid bearer returns bounded `401 unauthenticated` with no credential detail;
- a disposable valid credential works before revocation;
- revoke that disposable credential through the authorized admin lifecycle;
- the same credential then returns bounded `401` and cannot mutate admin state;
- do not revoke the credential needed by ordinary customer integrations.

### Rate limit and `Retry-After`

Using only a disposable credential, intentionally reach the authenticated per-credential limiter with a bounded request sequence derived from the current configured policy. Require:

- `429 rate_limited`;
- positive `Retry-After`;
- no token/verifier/internal limiter state in body/log output;
- unrelated credentials are not consumed by the disposable credential's bucket.

Do not change the production rate-limit policy merely to make the test shorter unless source inspection finds a release-blocking configurability defect already inside the contract. Do not launch an unbounded/high-concurrency request flood.

### Real snapshot-change response

Use the dedicated validation Profile and authorized admin mutation, not a debug endpoint:

1. obtain page 1 and retain its continuation cursor;
2. change a bounded Profile property/selector through the protected control plane in a way that legitimately changes the distribution snapshot revision while keeping the Profile otherwise valid;
3. request the retained cursor;
4. require real managed `409 snapshot_changed` rather than mixed pages;
5. restore the intended Profile configuration through the same control plane;
6. require a fresh initial traversal to succeed.

Do not mutate underlying tables directly and do not add an artificial production delay/fault route.

### Disabled API state

Temporarily disable only the dedicated validation Profile through admin and require authenticated `409 profile_disabled`. Restore/re-enable it before the P2 handoff and require a successful fresh read. P3 will separately prove that the PHP LKG suppresses/restores rendering correctly.

## Bounded release-blocker repair rule

P2 may modify implementation/tests only when real qualification exposes a concrete defect already inside the existing 2.0 contracts.

Allowed examples include a bounded migration-preservation bug, incorrect status/header mapping, credential revocation/rate-limit defect, telemetry secret leak, trusted-proxy release blocker, or other unambiguous defect that prevents the specified managed path.

For every repair:

- identify the governing invariant and root cause;
- trace important producers/consumers;
- add a focused regression test whenever technically practical;
- rerun every invalidated specialized suite/procedure;
- preserve the dedicated validation Profile/customer state and unrelated behavior.

If a repair requires a new deployment topology, new API behavior, new credential authorization model, new Profile semantics, a general refactor, or another material capability, stop with `Planning needed` instead of hiding it inside Phase 7.
