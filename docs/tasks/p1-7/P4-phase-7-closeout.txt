## Required final failure matrix

On the final candidate, require honest evidence for each state. Controlled fault-origin observations must be labeled separately from normal real-managed observations.

### Upstream/API/sync failure

- failed sync does not replace/corrupt active valid LKG;
- ordinary usable/stale-usable visitor rendering continues locally;
- no emergency visitor API fallback appears;
- a later real sync recovers.

### Malformed/incomplete candidate

- isolated qualification origin challenges the **real external PHP client/synchronizer/store**;
- partial/malformed candidate is rejected;
- prior real LKG remains exact/active;
- no malformed body leaks;
- real managed sync later succeeds.

### Snapshot revision change

Require both halves:

1. P2/closeout real managed API observation proves legitimate revision change yields real `409 snapshot_changed` for an old cursor;
2. P3/closeout external PHP observation proves candidate discard/bounded restart/LKG preservation when that class occurs, using real coordinated mutation if deterministic or the isolated fault origin when needed.

Do not claim the isolated fault origin alone proves the production API's revision semantics.

### Stale valid / configured cutoff / never synced

- stale valid state remains renderable by default with no hard cutoff;
- configured strict cutoff suppresses retained Articles without deleting recoverable state;
- fresh successful sync/restored config returns usable rendering;
- separate fresh state proves never-synced safe fallback with no live visitor request.

### Authoritative disable/re-enable

- real admin Profile disable -> real `409 profile_disabled` -> external sync records authoritative disabled -> customer page suppresses cached Articles;
- re-enable/restore -> successful real sync -> external page renders again;
- adapter does not infer disable from other failures.

### Invalid/revoked authentication

- external sync receives bounded auth failure with disposable/invalid credential;
- existing LKG remains governed by stale policy and is not marked disabled;
- valid replacement credential restores sync;
- no credential leaks.

### Rate-limit / Retry-After

- P2/closeout proves real managed `429` + `Retry-After`;
- P3/closeout proves external PHP retry/sleep/exhaustion behavior using a deterministic short qualification sequence rather than hammering production again;
- active state is preserved throughout.
