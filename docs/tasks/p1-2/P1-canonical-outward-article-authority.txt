## Required implementation behavior

Introduce the smallest coherent shared distribution-level repository/read-model boundary that owns canonical outward Article eligibility and normalized outward Article projection.

The canonical authority must own these rules exactly once:

- Source approval state must be `approved`;
- Source lifecycle state must be `active`;
- Source operational state is not an outward-eligibility gate;
- endpoint state/health and Collection-run success/failure are not outward-eligibility gates for retained Articles;
- Article visibility must be `visible`;
- an Article is eligible only when it is ungrouped or the Primary member of a Duplicate group;
- visible non-Primary members remain stored but are suppressed from ordinary outward results;
- stored `original_url` remains the reader destination without canonical-identity substitution or rewriting;
- effective headline is `display_title_override` when present, otherwise persisted `display_title`;
- effective feed date is trusted parsed `published_at` when present, otherwise `first_seen_at`;
- feed-date source is exposed as `published_at` or `first_seen_at`;
- deterministic canonical ordering remains effective feed date DESC, then `first_seen_at` DESC, then Article ID ASC;
- effective Category membership must honor the current moderation override model: active manual override memberships replace automatic memberships, including the intentionally empty-override case;
- effective Categories must expose stable `configKey` and `displayName` values in deterministic order;
- canonical Article projection must expose the normalized fields later required by the v1 distribution contract: Article ID, effective headline, exact stored original URL, effective feed date/source, nullable persisted `publishedAt`, nullable `author`, nullable `summary`, nullable `imageUrl`, Source `configKey`/`displayName`, and effective Categories;
- retain exact PostgreSQL microsecond-precision continuation/order keys for effective feed date and `first_seen_at` internally. Do not reduce ordering keys to JavaScript millisecond precision.

The shared boundary may expose narrower helpers needed by the existing public feed, but it must not introduce a generic query/expression framework or speculative transport/API abstractions.

## Existing public-feed behavior that must remain unchanged

Refactor `src/public-feed/repository.ts` to consume the shared canonical authority without changing the current external reference-feed contract.

Preserve:

- `public_status = public` as the exposure gate for `/` and `/api/feed` only;
- existing `q`, Source, and Category discovery semantics;
- current public server-defined page size;
- current public discovery cursor codec and criteria binding;
- current Source/Category discovery-choice behavior and bounds;
- current generic `400`, `404`, and `503` behavior through existing callers;
- current small public item shape: do not start exposing author, summary, image URL, source config key, Categories, or internal cursor keys merely because the shared canonical projection now contains them;
- current public keyword-search semantics, including matching effective headline plus the currently permitted Source-derived display-title/normalized-title fields, author, and summary;
- current public Category filtering over effective moderated Category state;
- current no-auth reference-feed behavior;
- current `/` and `/api/feed` routing and presentation behavior.

Important: Distribution Profile phrase matching in the next prompt will use only effective headline, author, and summary. Do not weaken or silently rewrite the existing public keyword-search contract in order to make the two filters share identical text fields.

## Focused proof and downstream handoff

Create focused real-PostgreSQL tests for the new canonical authority. Reuse or adapt existing public-feed fixtures where appropriate, but tests should prove the new producer directly rather than only indirectly through `/api/feed`.

At minimum prove:

- approved+active Source inclusion and unapproved/archived suppression;
- paused/disabled Source operational states do not suppress retained otherwise-eligible Articles;
- hidden/archived Article suppression;
- ungrouped/Primary inclusion and non-Primary suppression;
- hidden Primary does not cause a visible non-Primary member to be resurrected;
- exact stored `original_url` is retained even when `canonical_identity_url` differs;
- effective title override behavior;
- automatic Category state, manual override replacement, intentionally empty override, and restoration after clearing override;
- parsed publication date versus first-seen fallback;
- deterministic tie ordering;
- PostgreSQL microsecond precision across continuation/order keys;
- nullable author/summary/image URL mapping;
- Source config key/display name mapping;
- effective Category config key/display name mapping;
- malformed persistence rows remain bounded as repository/read-model failures rather than leaking raw database details where this boundary performs validation.

The downstream handoff must be auditable as:

`canonical eligibility + normalized outward projection + exact order position -> shared distribution producer/export -> focused PostgreSQL proof`

Before finishing, verify that a later Profile consumer can use the producer without inventing its own SQL for Source trust, Article visibility, Duplicate suppression, effective Categories, effective dates, canonical ordering, or `original_url` semantics.
