RAW QUERY BOUNDARY
Use the P1 raw-query parser against the request's raw query-string representation before Express query coercion can hide duplicate/encoding ambiguity.

Do not independently reinterpret:
- repeated parameters;
- percent encoding;
- config-key grammar;
- `q` normalization/bounds;

P1 owns those semantics.

The route must support exactly:
- `q`;
- `source`;
- `category`;
- `cursor`.

P1 parser failure must terminate before the repository read and map to one bounded generic public `400` response.

DEPENDENCY SHAPE
Change `PublicFeedDependency.read` from a parameterless function to one that accepts the normalized P1 discovery request.

Update production `src/app/web/main.ts` composition to pass that request into the canonical `readPublicFeed(database, request)` or actual final P2 equivalent.

Do not add a second production reader or wrap the old reader in a compatibility path that silently drops filters.

HTTP RESPONSE SHAPE
On public-success `200`, return one bounded JSON document with the semantic equivalent of:

- `publication: { name }`;
- `discovery: {`
  - `query: { q, source, category }` using normalized nullable/absent-safe public criteria values;
  - `sources: [{ configKey, displayName }, ...]`;
  - `categories: [{ configKey, displayName }, ...]`;
  - `}`;
- `items: [...]` using the existing exact safe item fields;
- `nextCursor: string | null`.

The `discovery.query` echo is intentional: it gives the Phase 12 browser one server-normalized source of truth for active safe criteria without exposing cursor internals or searchable private metadata.

Use one consistent nullable/optional representation and test it. Prefer explicit nullable fields for the three query criteria if that simplifies browser validation and stable JSON shape.

- `articleId`;
- ISO `effectiveFeedDate`;
- `feedDateSource`;
- `headline`;
- `sourceName`;
- `originalUrl`.

Do NOT expose:

- Source/Category UUIDs;
- canonical identity URL;
- observations/rules/reasons.

PUBLIC ERROR MAPPING
Preserve/cache `Cache-Control: no-store` on every `/api/feed` response.

Map outcomes exactly:
- malformed/repeated/unknown/out-of-bound query/cursor input from P1 -> `400` with one generic body such as `{ "error": "invalid_request" }`;
- structurally valid but unsupported/non-publicly-selectable Source or unsupported Category on a public Publication from P2 -> SAME generic `400` body;
- absent or non-public singleton Publication -> existing generic `404 { "error": "not_found" }`;
- database/repository/internal dependency failure -> existing generic `503 { "error": "service_unavailable" }`.

Do not distinguish malformed cursor vs bad Source vs bad Category publicly. Do not serialize error class names/reasons, SQL, UUIDs, attacker input, connection information, stack traces, or Publication private-state details.

ERROR PRECEDENCE
Rely on P2's private/absent Publication precedence for structurally valid filter probes. P3 must not perform a separate Source/Category existence lookup that can turn a private Publication into a `400` existence oracle.

Malformed raw request syntax may still return `400` before any repository read because no valid discovery request exists to evaluate.

UNFILTERED COMPATIBILITY
`GET /api/feed` with no query parameters remains the unfiltered first page of the same canonical feed.

It may gain the Phase 12 `discovery` metadata and `nextCursor` fields, but MUST preserve:
- current Article eligibility;
- current item fields;
- current ordering;
- current 200 empty-Publication behavior;
- current 404 absent/private behavior;
- current secret-safe 503 behavior;
- exact stored `originalUrl`.

Do not retain the historical exact pre-Phase-12 top-level JSON shape in a parallel compatibility mode. Update current tests/consumers to the one new canonical response.

CURSOR HTTP SEMANTICS
A request with valid `cursor` must also pass the current normalized `q`/`source`/`category` criteria through P1/P2.

Cursor/query mismatch is a generic `400` and must not reach a looser repository continuation path.

The public response treats `nextCursor` as an opaque string. Do not decode it in `create-app.ts` for response purposes or expose its fields.
