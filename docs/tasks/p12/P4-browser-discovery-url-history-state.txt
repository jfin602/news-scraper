GOAL

P4 owns FIRST-PAGE request concurrency correctness but deliberately leaves continuation/load-more to P5.

STATIC PAGE SHELL
Extend the root page with a small accessible discovery region containing the semantic equivalents of:
- keyword search input;
- Source select;
- Category select;
- Apply/Search control;
- Reset control.

Prefer real HTML form/select/input/button semantics and labels. JavaScript may intercept form submission to preserve the SPA-like root shell/history behavior.

The existing CSP currently includes `form-action 'none'`. Keep the CSP at least as restrictive; do not weaken it merely for the controls. If a `<form>` is used, normal scripted submission must call `preventDefault()` and not rely on a network form navigation fallback.

Reset must remain available even when the current URL/API request is invalid so a user can recover to `/`.

API METADATA AS SOURCE OF CHOICES
Populate Source/Category options only from the P3 public discovery metadata.

Do not hard-code:
- publisher names/keys;
- Category names/keys;
- indie-author/publishing-specific options.

Use `configKey` as option value and `displayName` as visible label.

When the API returns normalized active criteria, use that normalized server response as the authoritative successful-state criteria representation in the controls.

URL STATE CONTRACT
The canonical root URL reflects only non-empty Phase 12 discovery criteria:
- `q`;
- `source`;
- `category`.

Do not put `cursor`, internal IDs, page depth, sort, limit, or arbitrary client state into the shareable URL.

Use ordinary query parameters on `/`, for example:
`/?q=contract&source=publisher_key&category=industry_news`

Use deterministic parameter order when the client creates URLs: `q`, then `source`, then `category`.

Initial successful navigation/refresh must reconstruct the same logical criteria from the URL and render the matching first page.

INITIAL RAW URL REQUEST
For the FIRST load of the page, preserve server ownership of malformed query validation.

Prefer constructing the initial `/api/feed` request from the current root URL query string without silently decoding/re-encoding malformed percent sequences first. This lets the P1/P3 API correctly return `400` for malformed/repeated/unknown discovery URLs rather than a permissive browser parser repairing them.

Once the API returns successful normalized `discovery.query`, use that safe normalized criteria for controls and later client-generated URLs/requests.

If the current root URL includes malformed/unsupported discovery syntax, show the bounded invalid-discovery state and keep Reset usable; do not turn the bad URL into a different valid search automatically.

APPLY / SEARCH BEHAVIOR
On form submission:
1. collect the current control values;
2. trim keyword input;
3. omit empty keyword/Source/Category values;
4. build a deterministic root URL using `URL`/`URLSearchParams` from those safe control strings;
5. `history.pushState` the new root URL only when it represents the newly requested criteria;
6. invalidate any previous first-page request/result ownership;
7. clear prior results/pagination state;
8. request the matching FIRST page from `/api/feed` without cursor;
9. on success, render using the API's normalized active criteria and metadata.

Do not implement live search on every keystroke. One explicit Apply/Search action is sufficient for Phase 12.

RESET BEHAVIOR
Reset must:
1. clear keyword/Source/Category controls;
2. push or replace the canonical root URL `/` as appropriate for an explicit user action;
3. invalidate prior request ownership;
4. clear previous results/pagination state;
5. fetch the unfiltered first page;
6. repopulate metadata/control state from that response.

Do not reload the entire document solely to implement Reset unless a materially simpler correct history model requires it; prefer the existing client shell.

BACK / FORWARD BEHAVIOR
Listen to `popstate`.

On back/forward:
1. treat the browser URL as the source of requested discovery state;
2. invalidate any in-flight first-page request from the prior history entry;
3. clear prior results/pagination state;
4. request the URL-reflected first page;
5. restore controls from the successful API-normalized criteria;
6. never leave stale controls/results from the state being exited.

Do not call `pushState` from the `popstate` handler and create history loops.

FIRST-PAGE REQUEST OWNERSHIP
P4 MUST already prevent stale first-page responses from overwriting newer URL/control/result state.

Implement one explicit ownership mechanism, preferably:
- one active `AbortController` per first-page request; and/or
- a monotonically increasing request generation/token checked before every state commit.

Required properties:
- Apply during a slow previous request makes the older response irrelevant;
- Reset during a slow previous request makes the older response irrelevant;
- back/forward during a slow previous request makes the older response irrelevant;
- an aborted/stale request must not switch the current UI into error/empty/populated state;
- only the currently owned request may update Publication name, document title, metadata options, status, rows, or active criteria.

P5 will extend this state model to continuation requests; P4 must not knowingly leave the first-page path racy.

RESPONSE VALIDATION
Extend the current browser-side `validatedFeed` equivalent to validate the actual P3 response defensively before rendering.

Validate at minimum:
- Publication object/name;
- normalized discovery criteria fields;
- Source/Category option arrays and each `configKey`/`displayName` string;
- existing item array/item fields;
- nullable `nextCursor` as a non-empty string when present.

Do not decode `nextCursor` in the browser. P4 may store it in state for P5 but does not render/use continuation yet.

Treat malformed API JSON as generic feed error without rendering partial untrusted structures.

PUBLIC STATES
Preserve current meanings and add only what discovery needs:
- `loading` — current first-page request in progress;
- `populated` — matching first page has Articles;
- `empty` — public Publication exists but current criteria match zero Articles;
- `unavailable` — API 404 absent/private Publication;
- `invalid` — API 400 bounded invalid discovery URL/request;
- `error` — API 503/network/malformed successful payload/other failure.

Use bounded generic human-readable copy. Do not expose backend error text.

A filtered/search empty result MUST NOT say the Publication is unavailable.

RENDERING / SECURITY

Continue validating publisher URLs as HTTP/HTTPS before creating links.

Preserve exact stored `originalUrl` as link destination; do not route through the Platform or canonical identity URL.

Do not expose searchable summary/author/internal fields in the page merely because the backend searches them.
