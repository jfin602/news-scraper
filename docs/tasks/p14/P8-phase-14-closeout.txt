CLOUDFLARE / DIRECT-ORIGIN GATE — NARROW LEVEL 8 REQUIRED
Phase 14 introduces admin routes, so its exit gate requires observed evidence that the supported deployed admin surface is actually behind Cloudflare Access and cannot be reached through an unprotected origin path.

This narrow perimeter validation does not replace the broader Phase 19 production/reference-deployment hardening campaign, but it is mandatory for Phase 14 GREEN.

Using the currently supported/reference pre-production deployment and without exposing secrets in logs/artifact, record the actual mechanism and observe:

1. unauthenticated normal request to the deployed admin URL is intercepted/denied/challenged by Cloudflare Access before the application admin shell is available;
2. an authorized operator can reach the deployed admin shell through Cloudflare Access;
3. a direct-origin bypass attempt cannot reach a usable admin surface;
4. the observed direct-origin protection mechanism is identified accurately: Cloudflare Tunnel with no public origin route, origin firewall restriction, authenticated origin connectivity, or another documented equivalent actually in use.

The direct-origin attempt must match the actual topology. Examples include testing the public origin address/hostname with the appropriate Host/SNI context when such an origin exists, or proving there is no independently reachable public origin when Tunnel is the mechanism. Do not invent an origin address merely to perform a test.

Do not include Access cookies/tokens, authorization headers, tunnel credentials, database secrets, or other sensitive values in the durable artifact.

Local Express tests, Cloudflare configuration screenshots/source inspection, or the presence of `Cf-Access-*` headers alone are NOT proof that direct-origin bypass is prevented.

If the supported deployment is unavailable, Cloudflare Access is not configured, or direct-origin protection cannot actually be observed, record that limitation and Phase 14 remains blocked/red. Do not weaken the exit gate.

New Level 7 approved live-publisher collection is not intrinsically required solely by Phase 14 because deterministic Level 5 fixtures plus existing live-source history cover unchanged publisher transport semantics. If P1–P7 unexpectedly changed publisher transport/network behavior beyond governed Source admission, reassess whether Level 7 is required rather than assuming it is not.
