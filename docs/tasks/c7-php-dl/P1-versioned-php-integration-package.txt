It must not change Distribution Profile semantics, machine credential lifecycle/authentication, the v1 distribution API, PHP synchronization/LKG semantics, customer local-read semantics, or Phase 7 qualification behavior.

PACKAGE CONTRACT
The downloadable artifact is generic and MUST NOT be tied to a specific machine credential or Distribution Profile.

The ZIP filename exposed to P2 must be exactly version-bearing and safe, using this shape:

`news-scraper-php-integration-<deployed-version>.zip`

The archive must contain one stable top-level directory:

`news-scraper-php-integration/`

Within that root, package only customer-facing runtime/install material. Use an explicit allowlist; never recursively archive `integrations/php/`.

Required runtime membership at the current tree is:
- `README.md`;
- `bin/sync.php`;
- `example/index.php`;
- every PHP file required by `src/bootstrap.php`: `Http.php`, `Configuration.php`, `Client.php`, `Synchronizer.php`, `LocalState.php`, `FilesystemStateStore.php`, `LocalRead.php`, `Renderer.php`, `Runtime.php`, and `bootstrap.php`;
- `config/sync.env.example`;
- `config/local-read.env.example`;
- generated `VERSION`;
- generated `integration-package.json`.

Do not dynamically glob new files into the package merely because they appear under `integrations/php`. If the production runtime dependency set changes, the explicit package manifest must be intentionally updated and tested.

EXCLUSIONS
The ZIP MUST NOT contain:
- `integrations/php/tests/` or any test-only fixture/helper;
- repository root files unrelated to customer PHP installation;
- `.env`, credentials, bearer tokens, Authorization values, cookies, database URLs, private keys, host-specific secrets, deployment paths, generated LKG/cache state, logs, backups, runtime temporary files, or operator configuration;
- `package.json` from the Node application unless it is intentionally represented only through the generated bounded package metadata described below;
- source maps, Node modules, Composer/vendor files, or speculative installer/updater code.

DEFAULT CONFIG TEMPLATES
Add version-controlled customer templates under `integrations/php/config/` so the package contents are reviewable in source control.

`sync.env.example` must expose only supported synchronization configuration with safe placeholder values and actual current defaults:
- `NEWS_SCRAPER_BASE_URL=https://your-news-scraper.example` or equivalent clearly non-live HTTPS placeholder;
- `NEWS_SCRAPER_PROFILE_KEY=replace-with-profile-key`;
- `NEWS_SCRAPER_STATE_ROOT=/absolute/private/path/news-scraper-state` or equivalent;
- `NEWS_SCRAPER_BEARER_TOKEN=replace-with-machine-credential`;
- `NEWS_SCRAPER_SYNC_CADENCE_SECONDS=900`;
- `NEWS_SCRAPER_TIMEOUT_SECONDS=20`;
- `NEWS_SCRAPER_MAX_RESPONSE_BYTES=2097152`;
- optional `NEWS_SCRAPER_MAX_STALE_AGE_SECONDS` documented/commented rather than inventing a default hard cutoff.

`local-read.env.example` must contain only visitor/local-read configuration:
- Profile key;
- non-public state root;
- cadence `900`;
- optional stale-age setting.

It MUST NOT contain `NEWS_SCRAPER_BASE_URL` or `NEWS_SCRAPER_BEARER_TOKEN`.

Keep these templates aligned with the current PHP configuration classes. Do not add unsupported knobs.

VERSION / METADATA AUTHORITY
The package producer must derive the deployed News Scraper version from the same deployed repository tree that supplies the PHP files, rather than accepting arbitrary request/user input.

Generate:
- `VERSION` containing the exact top-level application semantic version plus a trailing newline;
- `integration-package.json` containing a small stable JSON object identifying at least the product/package name, exact News Scraper version, and API generation `v1`.

Do not include timestamps, hostnames, filesystem paths, credentials, or mutable deployment state in this metadata unless an existing authoritative runtime build identity already exists and can be included without expanding scope. The important invariant is package/source/version correspondence.

If top-level package metadata is missing, malformed, unsupported, or cannot be associated with the same repository tree as the allowlisted PHP files, fail closed rather than manufacturing a package.

ARCHIVE IMPLEMENTATION
Use Node core only for this correction. Do not add an npm dependency and do not invoke `zip`, PowerShell, Python, PHP, shell commands, or other external executables from the web process.

Implement the smallest standards-compliant ZIP encoding needed for this fixed package. Stored/uncompressed entries are acceptable; compression is not a requirement. Keep archive paths UTF-8, relative, slash-separated, deterministic, and free of traversal/absolute path forms.

Bound package generation so an accidental source change cannot turn an admin request into an unbounded memory/filesystem operation. Use explicit per-entry and aggregate byte limits appropriate to this small package, validate all allowlisted entries are ordinary files, and reject symlink/path escape behavior. Do not follow arbitrary links outside the package root.

Do not create generated ZIP files in the repository or a public directory. The producer should return a bounded in-memory package result suitable for a later HTTP response.

OWNING SERVICE / HANDOFF
Create one narrow package producer/service outside the canonical distribution read-model/authentication domains. It may live under an existing appropriate admin/integration infrastructure boundary; do not introduce a broad new architecture layer merely for one artifact.

Expose a small result contract sufficient for P2, for example conceptually:
- exact safe download filename;
- MIME type `application/zip`;
- exact deployed version;
- ZIP bytes.

The exact symbol names are implementation-owned, but P2 must not need to know:
- repository paths;
- PHP manifest details;
- ZIP header/CRC rules;
- version parsing rules;
- config-template generation rules.

Do not couple this service to `DistributionCredentialAdministrationService`, credential repositories, Profile repositories, PostgreSQL, or v1 API services.

`deployed repository tree -> package version authority -> focused version/metadata test`
