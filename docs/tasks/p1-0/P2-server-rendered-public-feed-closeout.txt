PASS 1 — CONTRACT / EVIDENCE REVIEW
Independently compare P1 against current governing contracts and actual source.

A. CANONICAL READ AUTHORITY
Verify:
- `/` calls the same existing public-feed dependency/application boundary used to source `/api/feed` semantics;
- SSR does not query Articles, Sources, Categories, duplicate tables, or moderation state through a second SQL/repository path;
- `src/public-feed/repository.ts` remains the canonical database-backed eligibility/filter/order/cursor authority unless P1 had a justified non-semantic support change;
- Source approval/lifecycle, Article visibility, duplicate Primary/ungrouped suppression, effective-date order, q/source/category behavior, and server-bounded page size remain unchanged;
- collection remains Worker-owned and root/API handlers perform no Source collection.

B. ROOT DISCOVERY BOUNDARY
Verify from source and tests:
- the root first-page parser is a narrow reuse of canonical decoding/normalization primitives rather than a second independent query-language implementation;
- ordinary form blanks for q/source/category behave as inactive root criteria;
- repeated, unknown, malformed, invalid-key, and out-of-bound forms fail closed;
- any root `cursor` is `400` in Phase 0;
- `/api/feed` still accepts governed valid cursors and retains its prior blank Source/Category behavior;
- unsupported Source/Category values are mapped to generic `400` without leaking the rejected value or private state;
- absent/private Publication still maps generically to `404`.

C. SERVER RENDERING AND STATUS
Verify raw HTTP behavior:
- populated and empty valid root states are `200`;
- invalid discovery is `400`;
- absent/non-public Publication is `404`;
- dependency/read/render-safety failures are `503`;
- all HTML outcomes retain `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, and the governed CSP;
- successful HTML contains Publication presentation, normalized controls, effective dates, headlines, Sources, and exact stored publisher anchors before client execution;
- successful root does not begin as a generic loading/unresolved shell.

D. CONTENT SAFETY / CSP
Verify:
- Publication, headline, Source, and discovery labels/values are escaped in the correct HTML context;
- attribute quoting cannot be broken by hostile strings;
- markup-looking content stays inert;
- emitted publisher destinations are absolute HTTP/HTTPS without credentials;
- same-origin logo path and canonical accent constraints remain safe;
- invalid injected dependency values fail closed rather than producing unsafe partial success;
- client API validation remains defense in depth;
- CSP grants only the required same-origin form submission (`form-action 'self'`) and does not add `unsafe-inline`, wildcard script/style/form permissions, or unrelated relaxation.

E. NO-JAVASCRIPT CONTRACT
Observe with a real browser context that has JavaScript disabled:
- root first page is useful and readable;
- direct q/source/category URLs show corresponding server results;
- native form Search submits to root and handles default All controls correctly;
- Source-only and Category-only navigation work;
- Reset is a real `/` navigation;
- headline is a normal exact publisher anchor;
- empty/400/404/503 states remain understandable;
- no cursor continuation has been added merely to satisfy no-JS Phase 0.

F. PROGRESSIVE ENHANCEMENT
Verify with JavaScript enabled:
- initial correct SSR state is adopted without an initial `/api/feed` request;
- initial masthead/feed rows are not cleared/reconstructed merely for startup;
- client internal criteria/item-ID/cursor state is coherent enough for later transitions;
- later Search/Source/Category and Back/Forward use the canonical API enhancement path without stale results/history pollution;
- Reset remains functionally equivalent to `/`;
- changing criteria drops old continuation state;
- Load More starts from the SSR cursor, remains criteria-bound, keeps cursor depth out of root URL, and retains duplicate-ID/repeated-cursor/empty-page/failure safeguards;
- theme changes remain request-free presentation state;
- broken-logo, presentation timezone, reduced-motion, keyboard/focus, responsive/mobile, and exact external navigation behavior remain protected.

G. VERSION / SCOPE / PRODUCTION DATA
Verify P1 did not introduce:
- migrations/schema/persisted representation changes;
- unsupported production-data rebuild assumptions;
- new dependencies or lockfiles without an explicit justified need;
- topic-specific indie-author logic;
- Phase 1 cursor links/page-size behavior;
- Phase 2 SEO metadata/sitemap/robots/canonical behavior;

PASS 2 — ERROR / EDGE-CASE ADVERSARIAL REVIEW
Do not satisfy this pass by merely observing green tests. Derive failure hypotheses from the actual implementation and determine whether source/tests/evidence protect them.

At minimum investigate:
- `?source=&category=` from a native form incorrectly becoming `400` or an active empty filter;
- duplicate root parameters where one copy is blank being silently accepted;
- encoded/obfuscated `cursor` names bypassing the root Phase 0 rejection;
- malformed percent encodings or excessive query length reaching the feed dependency;
- valid API cursor behavior accidentally broken by root parser changes;
- unsupported Source/Category being mistaken for Publication unavailable;
- Publication becoming private/absent during a multi-query canonical read and leaking stale presentation;
- hostile Publication/headline/Source/choice text containing `<`, `>`, `&`, quotes, or closing tags escaping text/attribute context;
- publisher URLs using `javascript:`, unsupported schemes, usernames/passwords, quote-breaking values, or malformed absolute URLs;
- logo paths becoming protocol-relative, remote, query/fragment/backslash/control-character URLs;
- invalid accent/timezone/date values reaching HTML or throwing after a partial response;
- server and client formatting the same effective timestamp to different calendar dates under configured timezone boundaries;
- SSR emitting duplicate Article IDs that later make continuation state unsafe;
- an opaque cursor or Article ID bootstrap value being exposed in a way that permits markup/script injection;
- initial JavaScript startup still performing a hidden duplicate `/api/feed` request;
- client startup clearing SSR rows before successfully validating its bootstrap state;
- delayed client startup losing a logo error event that fired before listeners attached;
- initial SSR `nextCursor` failing to create the Load More control or client criteria binding;
- Search/Reset/history actions creating duplicate history entries or stale controls/results;
- stale in-flight first-page success/error/404 winning after a newer navigation;
- continuation results from old criteria appending after criteria changed;
- repeated/empty continuation cursors causing loops or duplicate rows;
- a failed continuation destroying already-rendered Articles instead of remaining local;
- JS-disabled form Search blocked by CSP or incorrect form method/action;
- JS-disabled Reset still implemented only as a button/event handler;
- 400/404/503 error pages leaking SQL, connection strings, rejected private values, internal IDs, or stack details;
- CSS/selectors assuming the old unresolved/loading shell and causing a visible regression or inaccessible state;
- mobile wrapping, focus order, theme persistence, or reduced-motion behavior regressing because SSR markup differs from client-generated markup;
- topic-specific strings or a second feed query path appearing only in server rendering.

For each plausible issue, classify it as:
- already protected by source + focused evidence;
- needs a bounded defect/test fix inside Phase 0;
- needs the Terra High refactor handoff below;
- needs replanning/contract work.

Any bounded fix must receive a focused regression test and invalidate/rerun every affected final evidence command.
