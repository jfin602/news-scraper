Add the PostgreSQL driver, a substantive `test:db` suite, and test-only helpers that create unique disposable PostgreSQL databases, execute test work against them, clean them up, and verify cleanup. TEST COMMAND CONTRACT

Recommended ownership:

Because `npm test` is the ordinary deterministic local development matrix, revise it so it selects only the ordinary non-environment-requiring suites that exist (for example unit + integration) rather than unintentionally including `test/database/**`. Do not make ordinary `npm test` require a PostgreSQL server.

RESERVED TEST-ADMIN BOUNDARY
The only administrative environment variable for disposable PostgreSQL test creation is:
- `NEWS_SCRAPER_TEST_DATABASE_ADMIN_URL`

Requirements:
- it is consumed only by test-support code, not production `src/`;
- explicit `npm run test:db` execution with the variable missing must fail clearly and nonzero;
- the parser/validator must accept PostgreSQL URLs only;
- invalid configuration errors identify the variable and a bounded reason without echoing the raw URL or credentials;
- do not read or fall back to a future ordinary application database variable for destructive test administration;
- do not infer that an arbitrary database is safe merely because the URL is reachable.

DISPOSABLE DATABASE HELPER
Create test-only helper ownership under a narrow path such as:
- `test/support/database/`

A recommended high-level API is conceptually:
- `withDisposableDatabase(async ({ databaseName, databaseUrl }) => { ... })`

The exact TypeScript names may differ, but the behavior must include:
1. connect through the dedicated test-admin URL;
2. generate a unique database name owned by the helper, such as `news_scraper_test_<unique-id>`;
3. validate the generated name against a strict expected pattern before using it in administrative SQL;
4. create the disposable database;
5. provide a connection URL/reference for test code without logging credentials;
6. execute the supplied test callback;
7. always attempt cleanup in `finally`;
8. close clients/connections before DROP;
9. drop only a helper-generated/strictly validated disposable database;
10. verify via the PostgreSQL catalog that the database no longer exists;
11. surface cleanup failure instead of swallowing it.

Use correctly quoted identifiers or an equivalent safe strategy for database-name administration. PostgreSQL database identifiers cannot be parameterized as ordinary query values, so destructive operations must be protected by strict helper-generated naming and safe identifier handling rather than string-concatenating arbitrary caller input.

The helper should support independent disposable databases so later parallel/concurrency tests can avoid sharing mutable database state.

FOCUSED UNIT TESTS
Add Level 2 tests for test-support configuration and destructive-operation guards, including at minimum:
- missing `NEWS_SCRAPER_TEST_DATABASE_ADMIN_URL` fails predictably;
- non-PostgreSQL/malformed URL fails safely;
- a synthetic credential-bearing admin URL is not reproduced in thrown error text;
- generated disposable database names match the allowed pattern;
- arbitrary/non-helper database names are rejected before destructive DROP behavior;
- test helper configuration does not consume an ordinary development/application database variable.

REAL POSTGRESQL TESTS
Using the dedicated admin prerequisite, add Level 4 tests proving at minimum:
- a unique disposable database is created successfully;
- test code can connect to that created database;
- state written in one disposable database does not appear in a separately created disposable database;
- the database is dropped after successful callback completion;
- the database is also dropped when the test callback throws;
- cleanup is explicitly verified in the admin catalog;
- cleanup failures are surfaced rather than silently ignored where technically testable without making the suite unsafe.

Use only synthetic tables/data created inside disposable databases.
