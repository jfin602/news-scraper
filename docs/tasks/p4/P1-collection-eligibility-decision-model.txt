Prefer a small dedicated file, recommended:
- `src/collection/decision.ts`

The decision module SHOULD expose stable string-literal types and small immutable result/value shapes, not an exception hierarchy for normal blocked outcomes.

Do not use free-form human strings as the only API contract. Optional bounded detail may exist later, but machine-readable reason must remain primary.

ELIGIBILITY EVALUATOR
Create a pure evaluator, recommended:
- `src/collection/eligibility.ts`

It should consume the existing persisted `EndpointConfigurationAggregate` (or a narrow readonly structural type directly compatible with it) rather than creating a second repository/read model.

An endpoint is state-eligible only when:
- Publication `activeForCollection === true`;
- Source approval is `approved`;
- Source lifecycle is `active`;
- Source operational state is `enabled`;
- endpoint approval is `approved`;
- endpoint lifecycle is `active`;
- endpoint operational state is `enabled`.

Return an immutable discriminated result such as:
- eligible/proceed; or
- blocked with `stage: 'eligibility'` and one stable reason.

The exact TypeScript field names may follow repository conventions, but callers must not need to parse exception messages to distinguish a normal non-collectable endpoint.

DETERMINISTIC PRECEDENCE
If an invalid/synthetic aggregate contains multiple blocking states, return exactly one deterministic reason in this order:
1. `publication_inactive`
2. `source_unapproved`
3. `source_archived`
4. `source_paused`
5. `source_disabled`
6. `endpoint_unapproved`
7. `endpoint_archived`
8. `endpoint_paused`
9. `endpoint_disabled`
10. eligible

This precedence is an implementation contract for reproducible diagnostics/tests. It does not merge or redefine the underlying states.
