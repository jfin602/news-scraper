# 3.0 Roadmap Changelog

This file is the lightweight accepted-history companion to `docs/roadmap/3.0-roadmap.md`.

It records material roadmap work and decisions after they are accepted. It is intentionally brief and non-authoritative: contracts define behavior, the roadmap defines scope and sequencing, and validation artifacts record observed proof. A changelog entry must never be treated as evidence that tests, runtime behavior, provider behavior, or deployment behavior occurred.

Entries should normally contain the date, package version when relevant, and one to three bullets. Record accepted roadmap activation/version transitions, meaningful implementation milestones, phase closeouts, and material owner-approved roadmap or contract changes. Do not add entries merely because work is planned, and do not duplicate detailed validation evidence here.
