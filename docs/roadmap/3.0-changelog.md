# 3.0 Roadmap Changelog

This file is the lightweight accepted-history companion to `docs/roadmap/3.0-roadmap.md`.

It records material roadmap work and decisions after they are accepted. It is intentionally brief and non-authoritative: contracts define behavior, the roadmap defines scope and sequencing, and validation artifacts record observed proof. A changelog entry must never be treated as evidence that tests, runtime behavior, provider behavior, or deployment behavior occurred.

Entries should normally contain the date, package version when relevant, and one to three bullets. Record accepted roadmap activation/version transitions, meaningful implementation milestones, phase closeouts, and material owner-approved roadmap or contract changes. Do not add entries merely because work is planned, and do not duplicate detailed validation evidence here.

## 2026-08-28 — Change-aware and environment-aware validation locked

**Package:** `2.0.0`

- Locked validation planning around a Test Necessity Matrix plus Test Environment Matrix so prompt validation is selected by actual blast radius and execution prerequisites rather than by an always-run superset.
- Locked `RUN` / `DEFER` / `N/A` planning semantics, exact-tree cross-environment evidence, and no automatic retry for deterministic prerequisite/environment failures while preserving fail-closed behavior for explicitly invoked specialized suites.
- Planned unchanged-version correction stack `c1-test-fix` to make the ordinary local regression path portable and separate VPS-required PHP/PHP-browser evidence without lowering final closeout gates.

## 2026-08-28 — Gemini Phase 1 grounding and summary bounds locked

**Package:** `2.0.0`

- Locked the initial Gemini Phase 1 provider profile around the Gemini Developer API/Interactions API, `gemini-3.7-flash`, structured stateless output, governed URL Context over exact Profile Article `originalUrl` values, and no general Google Search grounding.
- Locked N6WD at a 4,000-character normalized persisted `Article.summary` maximum with complete-word truncation plus `...`, including the supported-production forward data transformation requirement.
- Preserved bounded summary fallback for paywalled/unavailable Article-page retrieval and kept provider/retrieved content downstream, untrusted, topic independent, and non-critical to ordinary Article delivery.
